# The cgame listen-server runs

The record of the first client runs of the Swift cgame. PR 42, branch `cgame-listen-test-1`, merge `d19ede5`, holds the five fixes. The runs and the findings come from the client logs under `/tmp/jka-client/`, the crash reports, and the engine instrumentation in `openjk/codemp/qcommon/msg.cpp`.

## The setup

- `/tmp/jka-client/home/swift/` holds `jampgamearm64.dylib` and `cgamearm64.dylib`, copied from `.build/debug/libjampgame.dylib` and `.build/debug/libcgame.dylib`.
- `/tmp/jka-client/home/base/uiarm64.dylib` is the ui module of OpenJK, copied from `.build/openjk/codemp/ui/`. The engine loads a ui module, and the port has none.
- The launch line is `.build/openjk/openjk.arm64 +set fs_homepath /tmp/jka-client/home +set fs_basepath "<Steam>/Jedi Academy/SWJKJA.app/Contents" +set fs_game swift +set sv_pure 0 +set vm_game 0 +set vm_cgame 0 +set vm_ui 0 +set logfile 2 +set cg_showmiss 1 +devmap mp/ffa1`. Stdout and stderr go to `/tmp/jka-client/client.log`.
- The engine writes its console to `/tmp/jka-client/home/swift/qconsole.log`. This file has the same content as the log of the last run.
- A crash writes `~/Library/Logs/DiagnosticReports/openjk.arm64-<date>-<time>.ips`. The cgame frames of the crashed thread name the Swift file and line.
- `RSEAM` lines come from `openjk/codemp/qcommon/msg.cpp:2540`. They belong to the engine instrumentation and not to the port.

## The five fixes

Each fix removes the trap or abort that one crash report showed. The commits stand in this order in PR 42.

1. Commit `1fa019d`, the drop shadow style bit. `Sources/JKAMP_CGameLogic/cg_draw.swift:490`, `493`, `496`, and `499` read `Int32(bitPattern: STYLE_DROPSHADOW)`, Raven's int cast. `Int32(STYLE_DROPSHADOW)` trapped because the constant does not fit in an Int32 as a value. Led from run 1.
2. Commit `5179068`, the particle chain. `Sources/JKAMP_CGameLogic/cg_marks.swift:465-466` sets `particles[i].next` to nil at the last slot. Raven takes the address one past the end and overwrites it on the next line. The change carries a rule 24 line. Led from run 2.
3. Commit `a90f5a1`, the ghoul2 index test. `trap_G2API_HasGhoul2ModelOnIndex` in `Sources/JKAMP_CGame/Generated/cg_syscalls.swift:1471` takes `inout OpaquePointer?` and passes the address of the handle, because the engine reads a `CGhoul2Info_v **`. The new kind is `out_opaque`. The 16 call sites pass `&(...ghoul2)`: `cg_ents.swift:1003`, `1008`, `1074`, `cg_event.swift:2721`, `cg_players.swift:7384`, `7434`, `7439`, `cg_servercmds.swift:1110`, `1112`, `cg_weapons.swift:547`, `659`, and the others in that commit. Led from run 3.
4. Commit `582a6cf`, the powerup icon loop. `Sources/JKAMP_CGameLogic/cg_draw.swift:3749-3750` stops at `j < PW_NUM_POWERUPS`. Raven reads `powerups[PW_NUM_POWERUPS]`, one past the end of the 16-slot array. The change carries a rule 24 line and falls under rule 19. Led from run 4.
5. Commit `777742e`, the syscall shim. `Sources/CJKASyscall/jka_syscall.c:21` adds `case 14`. `Sources/CJKASyscall/include/jka_syscall.h:11` and `Sources/JKAShared/EngineTransport.swift:4` now read 0 through 14. `trap_FX_AddLine` of the cgame passes 14 arguments, one more than any game trap. Led from run 5.

## Rows

- The duplicate Swift class warning at load. The game and the cgame dylibs each embed `JKAShared` and `JKAMP_BG`, because `Package.swift:44` and `:54` build them as targets that `jampgame` (`Package.swift:62`) and `cgame` (`Package.swift:63`) each link. When both load in one process, the runtime prints four lines (`client-run6.log:160-163`): `SharedChannel`, `StringPool`, `BgStorage`, and `BgState` are "implemented in both" `jampgamearm64.dylib` and `cgamearm64.dylib`. Raven's two modules also hold the bg files twice. The cold-boot run that loaded only the cgame printed no such line.
- The crash path through `G_ShutdownGame` and `trap_G2_HaveWeGhoul2Models`. A signal in the cgame reaches `Sys_SigHandler`, which calls `SV_Shutdown`, `SV_UnbindGame`, and `VM_Call` into `vmMain` of the game (`jampgame.swift:49`). `G_ShutdownGame` (`g_main.swift:973` in run 5, `g_main.swift:989` in runs 1 and 2) calls `trap_G2_HaveWeGhoul2Models` (`g_syscalls.swift:2023`), and `SV_GameSystemCalls_Real` faults at address `0x350`. A report of runs 1, 2, and 5 therefore shows the game's shutdown frames at the top and the cgame frames below the `_sigtramp` frame, and the cgame frames hold the cause. Reports 3 and 4 end in the renderer (`G2API_HasGhoul2ModelOnIndex`, `RB_SurfaceGhoul` through `RE_Shutdown`) and show no game frames.
- The 14-word shim comment. `Sources/CJKASyscall/jka_syscall.c:23` reads "No Raven trap passes more than 14 arguments, trap_FX_AddLine of the cgame, so a wider call is a module bug." The shim is one C unit that both the game and the cgame link, so the comment holds for both units. The header comment at `jka_syscall.h:11` and the doc comment at `EngineTransport.swift:4` state the same bound.
- The steady small prediction errors during movement on the foreign server. Run 8 printed 26 `prediction error` lines (`client.log:185` to `714`) in about 23 seconds, in groups of 3 to 9 per second while the player moved. Raven prints the line in `oracle/codemp/cgame/cg_predict.c:1246` when `oldPlayerState.origin` differs from the adjusted predicted origin and `cg_showmiss` is on. The port has the same test in `Sources/JKAMP_CGameLogic/cg_predict.swift`. The three `Prediction miss` lines (1664.665283, 310.979950, 21.097601) are larger decays of the same error.
- The four double event warnings at the shield booster pickup. Run 8 printed `Obtained Small Shield Booster` at `client.log:352`, then `WARNING: double event` at lines 353, 355, 357, and 359 within one second, with `RSEAM` lines between them. The correction to the task text: Raven's warning stands in `CG_PredictPlayerState`, `oracle/codemp/cgame/cg_predict.c:1471`, not in `CG_CheckEvents` (`oracle/codemp/cgame/cg_event.c`, port `cg_event.swift:3318`). It prints when `cg.eventSequence` is greater than `cg.predictedPlayerState.eventSequence` after `CG_TransitionPlayerState`, and the port has the same test at `Sources/JKAMP_CGameLogic/cg_predict.swift:1310`. Run 6 printed one such warning after `Obtained Imperial Heavy Repeater` (`client-run6.log:1368`).
