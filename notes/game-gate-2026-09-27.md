## Parse errors

NPC_goal ReachedGoal produces an unterminated block comment. Swift nests `/*` inside a comment, and C does not. Raven's C carries a dead branch inside `ReachedGoal`, with a `/*` block that itself holds a shorter `/* ... */` pair as plain text. `gap()` in draft_statements.py copies these lines as they stand. C reads the first `*/` as the end of the whole comment, so the shorter pairs close and reopen cleanly. Swift reads each `/*` as one more level of nesting, so the outer comment never gets its matching close, and the rest of the file falls inside it. This is NPC_goal.swift:241, the site of the C code below.

```
VectorSubtract ( NPCInfo->tempGoal->currentOrigin, NPC->currentOrigin, vec);
//Who cares if it's in our FOV?!
/*
// is it in our FOV
vectoangles ( vec, angles );
delta = AngleDelta ( NPC->client->ps.viewangles[YAW], angles[YAW] );
if ( fabs ( delta ) > NPCInfo->stats.hfov )
{
return qfalse;
}
*/
```

NPC_AI_Droid Droid_Patrol produces a float literal with no leading digit. C accepts `.5` as a valid float. `literal()` in draft_expressions.py strips only the trailing `f` suffix off a floating literal, and passes the rest of the text through unchanged. Swift requires a leading `0`, so `.5` is not a valid floating point literal. This is NPC_AI_Droid.swift:111, in the line below.

```
NPCInfo!.desiredYaw = Float(Double(NPCInfo!.desiredYaw) + Double(sin(level.time * .5)) * 25)
```

g_vehicles Board produces a Hole reason with a newline inside it. `binary_op()` in draft_expressions.py reads the raw source bytes between two operands to find the operator token, and when that span crosses a macro line such as `#ifdef _JK2MP`, the bytes carry a real newline. `hole()` in draft_classification.py writes the reason on one `// Port-note:` line with no escaping, so the second line of the reason lands on its own line, outside the comment, as bare code. This is g_vehicles.swift:312, the site of the draft below.

```
// Port-note: No operator between the operands, the text there is `||
#ifdef _JK2MP`.
```
