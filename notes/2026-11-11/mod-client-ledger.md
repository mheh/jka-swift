# The ledger of the mod client docket

The rows come from the probe of a client package that imports `JKAMP_GameLogic`, `JKAMP_CGameLogic`, and `JKAMP_DedLogic` together, and from the user's aim: a game mod that is a Vapor package with the server logic and the game logic in one process.

| 1 | The include of a per-module copy | Ratified as proposed, with the user's words "build in a linux container to test". `merge.py` writes the include of a per-module copy relative to the file that includes it, when that file is not at the include root. Each header stays at its path, and each unit keeps its own copy. The unit prefix on the path is not taken. Proof: line 7 of `enum_ID_AFFECT.h` and of `enum_TYPE_WAIT_COMPLETE.h` in `CJKAMP_Game` and in `CJKAMP_Ded` name a sibling from the include root, `wrap` at `merge.py:619-621` writes that form, and a copy of the repo with the four lines changed builds and runs a client with the three imports on macOS and in a `swift:6.4-noble` container on Linux. | 11 | The dynamic flag when Xcode builds the mod | Ratified as proposed, as an amendment of row 8. `Package.swift` reads the environment variable `JKA_IMPLICIT_DYNAMIC`.
