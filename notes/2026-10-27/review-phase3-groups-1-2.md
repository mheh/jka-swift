## The V35 patch

The wrapper test in `slot_refs` is sound for the case it names. A node with the same extent and kind as its child is in practice a stacked implicit cast, two `UNEXPOSED_EXPR` nodes over one read. With the test, the inner node maps to the parent of the outer node, and `slot_parent` skips both casts anyway, so no store or read changes class. Without the test, the second write of the shared key points the inner node at the outer node, and the outer node at itself, so `slot_parent` loops. The test does not hide a case among the seven plain locals and the one closure local of the record.

The test leaves one class open, and that class predates the patch. The key `(start, end, kind)` is not unique. In a macro expansion, libclang gives many nodes the extent of the macro call. An alternating chain at one extent, `UNEXPOSED_EXPR` over `PAREN_EXPR` over `UNEXPOSED_EXPR`, still makes a two-node cycle in `slot_parent`, and sibling nodes of one expansion share one entry, so a parent read can give the wrong node. A key by cursor removes the class, so the first finding of group 2 is the fix.
