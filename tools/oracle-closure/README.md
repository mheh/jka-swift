# oracle-closure

These scripts parse the oracle with libclang and answer layout and dependency questions about Raven's types and functions. They are a copy of `jka-rust/tools/closure-prototype` at the tree of jka-rust commit `70582e59`. `NOTES.md` holds the verdict and the lessons from the jka-rust run.

## What each script does

- `closure.py`: the parse core. It gives the transitive dependency closure of one type or function, its by-value or pointer-only class, and its size and field offsets. `project.toml` holds the per-unit compile flags, mirrored from Raven's vcproj Release configs, and the paths the sweeps read.

  `[targets]` of `project.toml` holds one row per unit that a generator run takes, `mp-game`, `mp-cgame`, `mp-ui`, and `mp-engine-ded`. A row names the source folder, the trap file, the logic target of the stubs, the view target, the C target, the names of the state files, the jka-rust crate, and the store. The cgame row also names the four vehicle files of the game folder that Raven's cgame build compiles a second time, under `borrowed`. The cgame run writes their stubs into its own logic target with Source lines in the game folder, and its sweeps read them as files of the cgame. `skeleton.py`, `manifest.py`, `rosetta.py`, `lookup.py`, `traps.py`, `channel.py`, `views.py`, `bodies.py`, and `draftcheck.py` take `--unit mp-cgame`, and `mp-game` is the default, so a command line with no `--unit` reads the game. `manifest.py` and `rosetta.py` write the manifests and the type stones of the default unit under `.claude/manifest/` and `.claude/rosetta/`, and those of each other unit into a folder of the unit's name below them, `.claude/rosetta/mp-ui/`. A `rosetta.py` run deletes the old stones of its own folder only. `closure.py` reads the unit from the command line at import, because the generator modules read the row at import. A unit whose logic target is not under `Sources/` yet writes every file of its run under `out/<unit>/` at the same relative path and says so in one line, and `draftcheck.py` drafts its stems there and builds nothing. The header parse of a run reads the umbrella of the unit's C target. `reexport.py` takes no unit, because it writes every C target whose view target is under `Sources/`, and a target reads only the names of the targets its umbrella reaches.
- `fnsweep.py`: the function manifest for one module, from one unity parse.
- `symsweep.py`: the symbol manifest. It lists every macro constant, enum constant, and file-scope global a module references.
- `pass2lib.py`: the worktree scanner the two sweeps use to mark items as ported.
- `merge.py`: the second pass. It reads the `extract.py` trees, compares every declaration across modules and trees by code identity, and writes the C targets: `CJKAShared` for what MP and SP agree on, `CJKAMP` and `CJKASP` for what each tree's modules agree on, and `CJKAMP_Game`, `CJKAMP_CGame`, `CJKAMP_UI` and their SP twins for the rest. A type is shared only when everything it includes is shared. Each target is a SwiftPM C target: the umbrella, the module map, and the headers under `include/`, with the translation unit and `layout_asserts.h` beside it. `merge.py --out ../../Sources` writes the package's targets, and the default writes `out/merge/` for a dry run. A module folder with no `extract.json` stops the run, because a check run of `extract.py` leaves the folder and no manifest. Two module targets can hold a per-module copy at one path, so a file below the include root names a per-module copy of its own target relative to its own folder, `#include "enum_TK_BLOCK_START.h"` in `enum_ID_AFFECT.h`, and a client that imports both targets finds the copy of each.
- `reexport.py`: the Swift re-exports. It parses each C target's umbrella and writes one Swift file per Raven header under the view target's `Generated` directory: a macro as a `public let` that reads the C value, an anonymous enum's enumerators as plain constants, a named enum as a struct with one static per enumerator, and a scalar typedef as a typealias. Swift's importer refuses a macro with an expression body and offers no way to ask which, so `--probe` builds, reads the failing lines, and moves each rejected name one rung up a ladder: the C body spelled as a Swift expression, the same expression narrowed to `Int32`, then a `TODO: Port` marker with the C text. A typedef that `ENUM_TYPEDEFS` of `rulings.py` names, `memtag_t`, is the `Int32` alias of a C enum under one rule 24 line, because its values are the enumerators of an anonymous enum. `--target JKAMP_Ded` writes one view target and reads the names of every other target from its files, and the option repeats for several targets. A file whose macro names a C library function, such as `strcasecmp` for Raven's `stricmp`, imports Foundation, because the internal import of the C target does not carry the C library on Linux. Run the re-export step on a tree that builds. `probe()` collects only the error lines that name a `public let` in a generated file, so a build that fails for another reason gives no names, and the run exits 1 with the first error line of that build.
- `skeleton.py`: every function of the MP game module as a stub, one Swift file per Raven `.c` file under `Sources/JKAMP_GameLogic` and `Sources/JKAMP_BG`, in Raven's order, with Raven's block as a `/** */` comment, a `/// Source:` line, Raven's signature by the same table, and the marker pair of rule 14 as the body. Access follows Raven's linkage. Raven's `static` becomes `private`, and so does every copy of a name that more than one file defines, except a function the oracle stores in a callback field, which a thunk names. Every other function is `public` in its target, except a bg function with the name of a public function of `JKAShared`, `atof`. A global that Raven declares without `static` is `public`, and its forward has a setter where Raven wrote no `const`. A file-scope `let` of a global with no `const` is `public` too, because no line that the product compiles writes it. A bg variable is a `var` when a unit beside the two parses of the game run writes it, because that unit's build compiles the bg file too, so the game run also parses the ui and reads its writes, `bgForcePowerCost` of `ui_force.c`. Such a write counts only for the variable of the file that declares the name. A bg data table of integers that a body writes is a stored property of `BgVariables` with Raven's brace list as a Swift array literal, each of his lines and comments in place, and a table whose values or counts the literal cannot hold keeps the hand form of a written data table. The second output is `Sources/JKAMP_GameLogic/Generated/Callbacks.swift`, one enum per callback field with one static thunk per stored function. A thunk of a unit whose view target holds a `ThunkReaders.swift`, the host, the cgame, and the ui, reads each word that file has a reader for: a text with `text(at:)`, a vector that the function takes by value with `vector(at:)`, and a `vec4_t` that the function takes by value with `vector4(at:)`. A C `char` that the function takes as an `Int32` widens with `Int32(_:)`. A host thunk hands back a returned text through `ringText(_:)` and a returned block as `OpaquePointer(block)`. A thunk with an argument that no reader turns into its parameter keeps the marker. A `.c` enum that `extract.py` leaves in its `.c` file because another `.c` file declares its names differently is `private let` constants at the top of the stub, read from the `file_enums` rows of `out/extract/mp-game/extract.json`, and a run with no `extract.json` for its unit stops and names `extract.py`. A stub file whose first line is no longer the generated header is adopted and left alone. `--only g_mover` prints one file. `--publish` puts `public` on the declarations that Raven's linkage names in the adopted logic and bg files and changes no other text. It leaves a declaration whose head names a type that its target declares without `public`, and it prints each one with its line and the reason. A file-scope `let` and a get-only forward of a global with no `const` take `public`. A function local that `BYTE_STORAGE_LOCALS` of `rulings.py` names is a variable of its file at its first declaration, one zeroed byte allocation on the storage class that every function the entry lists shares. An `int` local of the entry is a `Slots<Int32>` of its count, and an `int` parameter of the entry is a `Slots<Int32>` of one slot whose name takes the function name as a suffix, `key_Com_BlockChecksumKey`. An `unsigned int` local and a local of a `TYPES` typedef are a `Slots` of the Swift scalar, `UINT4 x[16]` a `Slots<UInt32>`, an `unsigned char` local is a `Slots<JKAShared.byte>`, and a `vec3_t` array local is a `Slots<JKAShared.vec3_t>`. A key of a local and its function, `("regs", "IsKNI")`, gives that function its own allocation, whose name takes the function name as a suffix, `regs_IsKNI`. A scalar data table that `SCALAR_DATA_TABLES` names, `PADDING` of md4.cpp, is C storage that `tables.py` copies, and its stub entry says so. A second overload of one name in one file whose parameters the table cannot shape is a marker with no function, because both would spell the empty signature, `G2_SetupModelPointers` of G2_API.cpp. A file-scope variable whose initializer is a constant of the logic target alone, `GORE_TAG_UPPER` of G2_misc.cpp, takes the hand line of the state object, because the view target holds the variables struct. The rule 24 line of a static local of `BYTE_STORAGE_LOCALS`, `nullSym` of VM_ValueToFunctionSymbol, says static and not stack. A C++ default argument keeps its default on the Swift parameter, except on an `inout` parameter, which Swift gives no default, which `cxx_default` reads from the definition or the first declaration into the `default` field of the `Param`: `false` or `true` for a `bool` or a `qboolean`, a number as Raven wrote it, `nil` for a NULL into an optional, and an enumerator by name.
- `spelling.py`: the one owner of the Swift type a C type has. One question lives there: for this C type and this role, the field of a view, a parameter, a return, a local, or an expression, what is the Swift spelling, and which conversion crosses into it. It reads `SCALARS` and `NARROW` of `reexport.py` and the tables of `rulings.py`, and holds the shape rules over them. `table.py`, `views.py`, and `bodies.py` ask it and keep no branch of their own. A typedef that `TYPES` names keeps its spelling behind a pointer or an array, where the canonical type loses the name, so `UINT4 *` is `inout UInt32`. A `byte *` or an `unsigned char` array of a host function that is not a trap is a `Slots` of the bytes, and a game function with that shape keeps its marker. In a host function, a scalar pointer that the body indexes and a fixed scalar array that the body writes are a `Slots` of the scalar, and a `void *` or `byte *` of PARAMS kind `bytes` is a `Slots<byte>`. A C++ reference to a record is the record's view, a pointer to a C++ class of `C_STRUCT_CLASSES` is the class's view, a parameter of PARAMS kind `word` and a return of RETURNS kind `word` are `Int`, a function pointer of PARAMS kind `callback` is the callback typealias of a view field, and a record return of RETURNS kind `record` is the record's view. A `char **` list of zone texts is `[String]` by the RETURNS kind `string_list` and the PARAMS kind `string_list`, `inout [String]` by the PARAMS kind `string_list_mut`, and `inout ArraySlice<String>` by the PARAMS kind `string_slice`, or `inout ArraySlice<String?>` when the body stores NULL into a slot, and a qsort comparator over texts takes `String` by the PARAMS kind `string_value`. A C++ `std::string &` of PARAMS kind `std_string` is `inout String`. A read-only `float *` point of PARAMS kind `vec3_const` is `vec3_t`, a plane of PARAMS kind `vec4_const` is `vec4_t`, and a `vec3pair_t` is `[vec3_t]`, inout when the body writes it. A `vec3_t *` or a `float *` of PARAMS kind `table` is `Slots<vec3_t>`, a `void **`, `byte **`, or `char **` of PARAMS kind `bytes` is `inout Slots<byte>?`, an `int *` of PARAMS kind `bytes` is `Slots<Int32>`, and a `byte *` return of RETURNS kind `bytes` or `optional_bytes` is `Slots<byte>` or its optional. A reference or a pointer to a C++ class of `CXX_CLASSES` is the hand Swift class of the same name, optional for a pointer and for a return of RETURNS kind `class_ref`. A RETURNS row `("class_ref", class)` names the class of a `void *` return. A non-const `char *` of PARAMS kind `text` is `String`, for a read that the text sweep cannot see.
- `table.py`: the C-to-Swift table of `abi-stubs.md` row 2, shared by `traps.py` and `skeleton.py`. It gathers the sweep facts and the rulings of a cursor, hands them to `spelling.py`, and wraps the answer into the `Param` its callers read. A prototype parameter of a function-pointer parameter takes the PARAMS row keyed `("<function>.<parameter>", label)`, with the label `p<i>` for a prototype parameter that Raven gives no name. A `char *` out-buffer is a returned `String` only in a trap. A parameter of PARAMS kind `slot` or a return of RETURNS kind `slot`, a `node_t **`, is a `Slots` of one optional view over the slot. A record pointer return of RETURNS kind `table` is the `Slots` over the records, `BG_AnimsetAlloc`. A botlib `long *` that the NULL sweep reaches is the `UnsafeMutablePointer` of the WinDed width, `intvalue` of `PC_Evaluate`. The subscript sweep of a host also reads a scalar pointer parameter that a body indexes. The slot sweep finds each array of `char *` that a body stores NULL into, `singleHilts[numSingleHilts] = NULL`, and each file-scope array that a caller hands to such a parameter, so the element of each one is `String?`. The NULL sweep reaches a parameter through `NULL` or `0`, through a slot of such an array, and through a call of a function that returns NULL on one path, so the slot sweep and the return sweep run before it, and the last two follow a parameter that passes them on, and a `const char *` that such a text reaches is `String?`. Only a unit of `TEXT_NULL_UNITS` of `rulings.py` follows a slot or a return, the ui, because the sweep sees no NULL test of the caller. `UNIT_RETURNS` of `rulings.py` holds the RETURNS rows of one unit, `UI_Alloc` of the ui as `optional_raw`, and the cgame copy keeps `raw`. The table owns the facts about a function's locals the same way it owns the facts about its parameters. `Table.locals_of` gives them for one function, keyed by file stem, function, and name: which `char *` local walks a named buffer, which pointer local walks a table of records, and which names the body writes, writes once outside a loop, or takes the address of. The first read of a function computes the facts and every later read takes them from the store, so a generator that reads no body pays nothing. The cursor sweep leaves the body of every function behind for that read. The read carries the cursor sweep's rows forward instead of reading those stores again, and it asks `spelling.py` for the spelling of a local and holds no type branch of its own. `bodies.py` reads the result in one lookup and walks no body for it.
- `store.py`: the table cache of the sweeps, `table.sqlite` in WAL mode, outside version control. `Table.sweep()` loads the facts whose key matches and runs only the sweeps of a stale generation. A load is one read transaction, so a save from another run during the load cannot mix the rows of two saves. The base key covers every file the three parses read, the declared names and callback signatures of the generated declarations the views read, the tool modules `project.toml` lists, and the set of records with a view. The adoption key covers the base key and the first line of every stub, so a stub edit costs the store sweep alone. A stale generation names its changed files on standard error. `--rebuild` on a generator sweeps every generation again, and a deleted store file rebuilds on the next run. A run of `skeleton.py` or `manifest.py` also writes the signature rows that `lookup.py sig` and `lookup.py fn` read, as the `signatures` generation. Its key covers the adoption key and the hash of every stub the rows read, and the store keeps each stub hash. `lookup.py` rehashes those stubs alone, and on a mismatch it names the changed stubs on standard error, tells the user to run `skeleton.py`, and reads the manifests. The base generation also holds the syntax rows of every function body: `statements`, one row per statement in preorder with Raven's line and text, `comments`, and `macros`. The `lowered` generation holds the drafts. Its key covers the adoption key, the declaration lines of every Swift file under `Sources/`, and the modules `project.toml` lists under `lowering`, so a body edit under a signature keeps the key. `lowered` has one row per drafted statement with its form, and `lines` has one row per printed line with its statement, its role, its depth, and its text. A function lowers on its first read and saves its rows, and a change of the lowered key deletes every lowered row and line row. `rejected` holds the compile holes of the last draftcheck run under the lowered key, and a write keeps the rows of one key alone. `alignments` and `aligned_files` hold the line map of `align.py`. A reader command opens the store with `reader=True`, which writes nothing when the schema version matches, so the file keeps its bytes. On a store of another schema version, a reader open stops with one line that names the stored version, the version of the code, and `bodies.py`, and deletes nothing. A writer open deletes that store and makes it again.
- `sigcheck.py`: the check that each Swift function signature is the signature the table gives today, the `sigs` step of `tools/gate.sh`. It reads the signature rows of each unit from its store, as `lookup.py sig` does, and finds the Swift declarations of each name in the file of the row's Swift line, or in every file under `Sources/` for a row with no Swift line. A comparison ignores white space, a line break in the parameter list, a trailing `{` or comment, access words and other modifiers, attributes, a module prefix of a package module, and a typealias of the package. A default value, an `inout`, an optional, a parameter name, and a return type stay. It skips a row with a `TODO: Port signature` reason and a function of `NOT_PORTED`. `SIGNATURE_EXCEPTIONS` of `rulings.py` names each difference that a ledger row keeps, and the check prints each one with its row. The command exits 1 on a difference that the table does not name and on an entry that no longer differs, and 2 on a store that is missing or stale. `--unit mp-cgame` checks one unit, and the option repeats.
- `tests/`: the unittest tests of the store, the key, the loader, lookup, the project file, the syntax rows, the roles, the lowered rows and the printer, `align.py`, `compare.py`, `sigcheck.py`, the access rule of `skeleton.py`, the include of a per-module copy, the link name of the host's `BSTable`, and the dump block of `tools/referee/referee.py`. Run `.venv/bin/python -m unittest discover -s tests`, and add `SLOW=1` for the tests on the real parse. Each SLOW test works on a copy of the store in a temporary folder.
- `tables.py`: Raven's data tables as C storage, written to `Sources/CJKAMP/bg_tables.c` for the bg tables, `Sources/CJKAMP_Game/g_tables.c` for the six game tables, `Sources/CJKAMP_CGame/cg_tables.c` for the cgame tables, and `Sources/CJKAMP_Ded/ded_tables.c` for the four netField tables of msg.cpp, `PADDING` of md4.cpp, and the static zone blocks `gZeroMalloc`, `gEmptyString`, and `gNumberString` of z_memman_pc.cpp with Raven's `ZONE_MAGIC` line. The host's `BSTable` of GameInterface.cpp takes the link name `_BSTable_ded` in its `extern` line, so it does not collide with the game's `BSTable` in a client that links both units, and the C name and the Swift name stay `BSTable`. It holds one piece per table, each naming the oracle file and the first and last line of Raven's text, and it copies those bytes as they stand, so a copied range keeps Raven's CRLF and the tool's own lines are LF. A piece with no line range carries the tool's own lines alone, which is how the offset-macro pragma and the `#undef` of `_JK2MP` stand beside the tables. It reads no parse, so it runs right after `merge.py`, before `check.sh` compiles the target. `--print` prints both files and writes nothing.
- `traps.py`: the typed trap functions, one per Raven `trap_*` in `g_syscalls.c`, written to `Sources/JKAMP_Game/Generated/g_syscalls.swift`. It reads the run's one parse and its one swept table, takes every function whose body is one `syscall(...)` call, and maps each parameter by the table of `abi-stubs.md` row 2 through the typed `Syscall.call` overload of the view target. The NULL sweep walks the game unit and the cgame unit, so a parameter is optional when a caller in either unit hands it NULL. A `char *` beside an `int` named as a size becomes a returned `String`, a `vec3_t` is passed by address inside `withUnsafePointer`, and a trap with a parameter or return the table cannot map is emitted with a `TODO: Port signature` marker, Raven's C text, and a `portMissing` body. A trap that `HAND_TRAPS` of `rulings.py` names for the unit is a hand body in the `Syscall+` file of the view target, `trap_R_RegisterShaderNoMip` of the ui, so the file holds its Source line and declares nothing, and `channel.py` reads the `Syscall+` file for the install of the consumer. `--only trap_Trace` prints one trap.
- `views.py`: the Swift views over Raven's structs, one file per view type under the view target's `Generated/Views` directory. It walks the closure of the roots of the run's unit in `ROOTS` of `rulings.py` by value, by array, and by pointer, `gentity_t`, `gclient_t`, `level_locals_t`, and `playerState_t` among the game's and `cg_t`, `cgs_t`, and `centity_t` among the cgame's, and maps each field by `spelling.py`, which holds the table of `struct-views.md` row 2: a scalar as itself, `qboolean` as `Bool`, an enum as its re-exported struct, `vec3_t` as `SIMD3<Float>`, an array as a `Slots` over the field's address, `char *` as `PooledString?`, a nested struct and a struct pointer as views, and a stored function as its C type with a typealias per signature and a `run` method per field. A `FIELDS` row of kind `bytes` makes a `byte *` field a `Slots<JKAShared.byte>?`, and a row of kind `slot` makes a `T **` field a `Slots` of one optional view over the slot, which `slotAddress` of `Sources/JKAMP_Ded/NodeSlots.swift` reads as a slot address. A field whose name is `handle` or `raw` and has a `FIELD_NAMES` row takes the name of the row, `cvarHandle` for `vmCvar_t.handle`. A view in another module is built from its `OpaquePointer` handle, so no raw pointer crosses a module. A struct or union Raven left unnamed as the type of a field gets a view named for its owner and the field, `RefEntityData` for the `data` union of `refEntity_t`. A run writes the view target of its unit whole, and in `JKAMP` and `JKAShared` it removes a view only when no struct of its parse has the C name or when the run gives the struct another file, so the views of the other unit stay. The `Callbacks.swift` file of `JKAMP` and `JKAShared` keeps the callback types it holds for the other units, so a run writes the union of its own and those. A field of an `ENUM_TYPEDEFS` typedef, `eTag` of `zoneHeader_t`, is the `Int32` alias, and the accessor widens the C storage on a read and truncates it on a write. A field with no table row gets a `TODO: Port` marker with the C text. A `FIELDS` row of kind `bytes` on an `int *` field gives `Slots<Int32>?`, a row of kind `pointer_table` on a `T **` field gives `Slots<View?>?` with the widest count, a row of kind `slot` on a record pointer field adds `<field>Slot`, the slot of the field as a `Slots<View?>` of count 1, and a row of kind `opaque` gives `OpaquePointer?` and keeps the walk from the record behind it, the `FILE *` of `qfile_gut.o`. A named union that a root row names, `qfile_gut`, takes a view, and so does a union that Raven names by its tag alone when a root row names the tag, `cvalue` of be_ai_char.cpp. A `PARAMS` row keyed `record.field` shapes a parameter of a run method: `float_mut` gives an `inout` scalar, `bytes` on a `void *` gives a `Slots<JKAShared.byte>`, and `table` on a `vec3_t *` gives a `Slots<JKAShared.vec3_t>`. A `RETURNS` row of kind `raw` keyed the same way makes the run method return the block, `botlib_import_t.GetMemory`. A `FIELD_NAMES` row also renames a `void *` field, `packHandle` for `pack_t.handle`, and a `SLOT_BOUNDS` row also bounds the setter of a `char` array field, `symName` of `vmSymbol_t`.
- `bodies.py`: a first Swift draft of each function body, translated statement by statement from Raven's AST and printed to standard output. It never writes into `Sources/`. The `Drafter` is the one entry and holds the state of a draft, and the `Registry` beside it reads the `inout` positions of every Swift function already under `Sources/`. The emit stands in five modules by concern, each one a set of methods the `Drafter` takes: `draft_statements.py` for the statement forms, `draft_expressions.py` for the expressions and the operators read from a token span, `draft_calls.py` for a call, its arguments, and the overload it takes, `draft_declarations.py` for the locals, the parameter copies, and the scratch closures, and `draft_classification.py` for the view, Slots, entity, and text questions the other four ask. `draft_classification.py` holds the `Hole` a Port-note stands under, so every concern reads it from one place. `--stem bg_pmove` prints every draft of one file, and `--only PM_AddTouchEnt` prints one. The drafter writes the lowered rows and the line rows of each function into the store, and `printer.py` prints the text from the line rows. A line row names the innermost statement whose draft holds it, so a line inside a labeled frame names the label and a line inside a scratch closure names the record local. `--compile-holes` prints each statement the last draftcheck run rejected as a compile hole. The drafter reads `BYTE_STORAGE_LOCALS`: the declaration of such a local is a rule 24 line that names its forward, and a read of the local is the forward. A cast to `unsigned char *` handed to a `Slots<byte>` parameter is the `bytes` of the `Slots`, or the `Slots` itself when it holds bytes. A `Com_Memset` of zero with a `sizeof` size takes the forms of `memset`, `record.clear()` and `table.zero()`. A store into one byte of a `Slots<byte>` whose value C computes in `int` is the `[byte:]` subscript, `fout[byte: (bloc >> 3)] |= bit << (bloc & 7)`, and a byte local of the entry reads through its forward, `string_NET_OutOfBandData[0]`. A store of a `Slots<byte>` into a field of FIELDS kind `bytes` is the plain store, `mbuf.data = string_NET_OutOfBandData`. A call to a platform function that no header of the parse declares, `timeGetTime`, is a hole that names the function. A C++ `bool` and the C++ `true` and `false` are Swift tests as they stand, so `if ( !baseTime )` reads `if !baseTime` and `while ( true )` reads `while true`.
- `draftcheck.py`: the compile gate of `bodies.py`. It splices the drafts of a Raven `.c` file over the hand bodies of its Swift file in a mirror of the package under `.build-draft/` and builds the game product there, so no file of the working tree changes. A drafted func line keeps the access word of the hand func line it replaces, because an adopted file can make a static function internal for a hand table in another file. The report separates the holes the draft left, the cascade errors a hole caused, and the defects that stand on their own. `--stem bg_pmove` gates one file, `--stem bg_pmove,bg_misc` gates several in one invocation, `--all` gates every bg stem, `--game` every game stem, and `--every` both. A run parses and sweeps once, splices every stem into the mirror, and builds once per pass. Each error goes to the stem whose file the compiler names. A statement whose drafted line the compiler rejects is a compile hole on the next pass, by its file, its function, and its seq, and a stem with no such statement keeps its draft. After the last pass, each stem gets its own line, the mirror holds the hand text again, and a total line closes the run. The compile holes of the last pass go to the `rejected` table of the store. A row gate runs over the stub of the stem, and the readoption count is the stub count, because the `splices` table keeps one hash per function. The command exits 1 when a defect stands. The stem line counts the hand functions kept, so a gate over a file with a body edited by hand gives a different count from a gate over the stub. The cap `PASSES` holds for one run, over the stems of that run.
- `adopt.py`: the adoption of a stem after `draftcheck.py` ends at 0 defects. It splices the last draft of the stem from `.build-draft/drafts/` over its stub in the working tree, matched by Raven line, and deletes the generated header line. In a file already adopted, a draft replaces only a function whose body is still the TODO line and the `portMissing` marker of the skeleton, and a function with a hand body keeps it. A replaced function keeps its hand signature line and takes the draft body under it. `--stem cg_draw` adopts one stem, `--game` adopts every stem of the logic target with a draft on disk, and `--unit mp-cgame` resolves the stub and the drafts against the cgame target.
- `printer.py`: the text of the drafts from the line rows, and the layout of the drafter's output. It indents a row by its depth, joins Raven's trailing comment onto its line, drops the module qualifiers of a body line, and prints the hole count of the stem as the footer. It never reorders a row. Its command prints from the store with no parse and no libclang: `--stem bg_pmove` prints one file, and `--only PM_AddTouchEnt` prints one function. It computes the lowered key again from the stubs, the Swift declaration lines, and the lowering modules, and takes the C-inputs part from the stored base key, because only a parse computes that part. A stale key, a missing function, or a function with no line rows stops the command with one line on standard error and exit 1. A stem whose stub the store lists and that holds no function prints the footer alone. `--compile-holes` prints the three lines of a compile hole in the place of each rejected statement. A rejected declaration, or a rejected statement that opens a scratch or choice closure, changes the draft of the statements after it, which the rows cannot show, so the printer stops on such a function and names `bodies.py --compile-holes`.
- `layout.py`: the indentation step, the Port-note line, and the compile note, which the lowering writes and the printer prints.
- `lowering_key.py`: the lowered key and the language of the lowered rows, which `bodies.py` computes from its parse and the readers compute with no parse.
- `snapshot.py`: the gate of a tool change. `--out <folder>` writes the text of every generator that reads the table, one file each: `skeleton.py` and `manifest.py` per stem, `traps.py`, `channel.py`, `views.py`, and `bodies.py --stem` per stem of the bg, game, and shared targets, so `align.py --adopted` finds the line rows of every adopted stem after a check. `--check <folder>` writes a new snapshot to a temporary folder and compares the two by `diff -r`, exit 0 when they are equal and 1 when a file differs. `--unit` takes the snapshot of another unit, with no channel text for a unit other than the `[sweep]` unit and no trap text for a host. The snapshot folders belong to the caller and stay outside version control. The cache root `~/.cache/jka-swift` holds one folder per unit: `snapshot-stage-two-shared` for `mp-game`, `snapshot-mp-cgame` for `mp-cgame`, `snapshot-mp-ui` for `mp-ui`, and `snapshot-mp-engine-ded` for `mp-engine-ded`. A landing refreshes each folder in place with `--out`.
- `align.py`: the line map between a hand file and the drafts of its Raven file, with no parse. A hand function and a draft function match by their `/// Source:` line, as draftcheck splices them, and difflib compares their stripped lines. An equal line is `same`, and a line of a replaced block of equal length on both sides is `edited`, each with the line row it matches. A line the hand wrote in place of no draft line is `hand`, and so is each line of a forward or of a hand function whose Source line no draft holds. A function whose body between its signature and its closing brace is still the TODO line and the `portMissing` marker of the skeleton is `stub`. Else a function whose ratio is under 0.3 is `rewritten`, and its name and ratio go to standard error with the count of draft lines no hand line matches. Every line of a `stub` or a `rewritten` function has no line row. The command skips a hand file whose hash and lowered key match the stored ones. `--stem bg_pmove` aligns one file, and `--adopted` aligns every stem whose stub is adopted. It exits 2 when the store or the line rows are missing or stale.
- `compare.py`: what a hand file changed against the draft. `--stem bg_pmove` prints each hand line in state `edited` or `hand`: Raven's file and line, the function, and the role, then a `draft:` line and a `hand:` line. A `rewritten` or a `stub` function prints one line with its Source line and no texts. `--counts` prints the count of each state for each function. `--against <folder>` compares the stored line rows of the stem with the draft file of a snapshot folder and prints each differing line with its C line. The command exits 0 when nothing differs, 1 when a line or a function differs, and 2 when the store, the alignment, or the snapshot is missing or stale.
- `extract.py`: the type copier. It writes one C header per Raven struct, union, enum, or typedef, with the oracle path mirrored, plus a constants file per Raven header, `forward.h`, `all.h`, and `layout_asserts.h` with the oracle's sizes and offsets. Two names of one folder that are equal when lowercased, `uiimport_t` and `uiImport_t` of `code/ui/ui_public.h`, each take the first line of their declaration in the file name, `uiimport_t_11.h`, the form of `anonymous_{line}.h`, so the names are the same on every file system. A declaration the parse cannot read is dropped, and so is a declaration that names one of its names. A file listed in `adopted.json` in the output directory is never overwritten. `extract.json` lists each `.c` enum whose names another `.c` file declares differently under `file_enums`, with each enumerator's initializer text, for `skeleton.py`.

## The placement rules

A type lands in the tree target, `CJKAMP` or `CJKASP`, when every module of the tree that emits it agrees on its text, or when one module alone emits it from a Raven header two or more modules see, because `usercmd_t` in `q_shared.h` belongs to every module and only the game's type closure holds it. A type from a header one module sees lands in that module's target. The bg run reads `q_shared.h`, `bg_public.h`, `bg_local.h`, and `bg_saga.h`, and never `g_local.h`, so the game-private types stay in the game target and the bg types in the tree target. A type both trees define identically lands in `CJKAShared`, and a macro identical in both trees is shared only when every name its body uses is shared too.

A `.c` file's own object-like macros, such as `MOVER_LOCKED` in `g_mover.c`, and its own enums, such as `TAUNT_*` in `g_active.c`, go to `<dir>/<stem>_c/constants.h` and are placed per module, never unioned, because `bg_misc.c` defines `MAX_POOL_SIZE` one way under `QAGAME` and another way in cgame. Two kinds stay in their `.c` file and are reported: a name a header uses as an identifier, such as Raven's `#define currentOrigin r.currentOrigin`, which would rewrite the header, and a name two `.c` files of one module define differently, which one header cannot carry. An enum also stays when a header, a hand header of `HAND_FILES`, or a `.c` macro names one of its names, and when another `.c` file declares one of its names in a different enum, as the NPC_AI files do with `LSTATE_NONE`. An enum two `.c` files declare alike is copied once.

The engine module of the dedicated server takes part in the placement for the module ABI headers alone, `g_public.h` and `interpreter.h`, which the game and the server both include. Every other type the host emits lands in `CJKAMP_Ded`, and a type it reads with another text keeps a host copy there. A constants file of the tree whose macros the host reads with the same text stays the tree's file, so no header path stands in two module maps. A type that names a name of its header's prelude is placed per module, because each module declares the prelude's names for itself: the token enum of `interpreter.h` reads `TK_USERDEF` from `g_ICARUScb.c` in the game and from `tokenizer.h` in the server.

## The layout check

`extract.py` parses each module once per target triple and writes `layout_asserts.h` as one block per ABI under a guard on Clang's `__SIZEOF_POINTER__` and `__SIZEOF_LONG__`. Three ABIs cover every triple: `ilp32` for the 32-bit targets, `llp64` for 64-bit Windows, and `lp64` for 64-bit Linux and Apple. `TRIPLES` in `extract.py` lists the triples and the ABI of each, and the writer exits when two triples of one ABI give different asserts, so a target that breaks the grouping shows up as a run that fails and not as a block that lies. `check.sh` compiles every target for every triple with `-ffreestanding`, so no SDK is needed for a foreign one. The merge exits when a seam type, or a record it holds by value, has two sizes across the ABIs of one pointer width. `--host-only` skips the foreign parses for a quick run.

## The gate of a tool change

A change to a tool module runs `snapshot.py --check` against a snapshot of the code before the change, and the change moves no printed byte unless it means to. A warm check reads the stored lowered rows, so it tests the lowered key as much as the drafter. Every module the drafter imports is in `[store] modules` or `[store] lowering` of `project.toml`. A drafter import outside the two lists would leave stale rows under an unchanged key, and the check would pass on them.

## Setup

```sh
cd tools/oracle-closure
python3 -m venv .venv
.venv/bin/pip install libclang==18.1.1
.venv/bin/python closure.py --list-modules
.venv/bin/python closure.py mp-game playerState_t --layout
.venv/bin/python extract.py mp-game
clang -fsyntax-only -x c -std=gnu11 -Wno-everything -I out/extract/mp-game -I glshim out/extract/mp-game/layout_asserts.h
.venv/bin/python merge.py --out ../../Sources
.venv/bin/python tables.py
./check.sh ../../Sources
.venv/bin/python reexport.py
.venv/bin/python views.py
```

The developer creates `.venv` locally, as a folder or as a link to the `.venv` of another clone, and git does not track it.

`check.sh` compiles every merged target's translation unit as C with its dependency include directories and exits nonzero on the first failure. It compiles with Clang modules, as SwiftPM does, so an include of a dependency's header imports that dependency's whole module. A target that reads the SDK takes the SDK as its system root on an Apple triple and compiles as text on another triple, because the SDK's module maps build only for an Apple triple. Its one argument is the directory the merge wrote, `out/merge` by default. `EXTRACT_DEBUG=<TypeName>` makes `extract.py` print every include it adds for that type and why, for a dependency that looks wrong.

## Known gaps

The ported-status half of `fnsweep.py`, `symsweep.py`, and `pass2lib.py` scans Rust crates under `crates/`, and `symsweep.py` names a jka-rust worktree path. Those paths do not exist here. The oracle-side half of each script works unchanged. A later step points the ported-status scan at `Sources/`.
