# oracle-closure

These scripts parse the oracle with libclang and answer layout and dependency questions about Raven's types and functions. They are a copy of `jka-rust/tools/closure-prototype` at the tree of jka-rust commit `70582e59`. `NOTES.md` holds the verdict and the lessons from the jka-rust run.

## What each script does

- `closure.py`: the parse core. It gives the transitive dependency closure of one type or function, its by-value or pointer-only class, and its size and field offsets. `project.toml` holds the per-unit compile flags, mirrored from Raven's vcproj Release configs, and the paths the sweeps read.

  `[targets]` of `project.toml` holds one row per unit that a generator run takes, `mp-game` and `mp-cgame`. A row names the source folder, the trap file, the logic target of the stubs, the view target, the C target, the names of the state files, the jka-rust crate, and the store. `skeleton.py`, `manifest.py`, `traps.py`, `channel.py`, `bodies.py`, and `draftcheck.py` take `--unit mp-cgame`, and `mp-game` is the default, so a command line with no `--unit` reads the game. `closure.py` reads the unit from the command line at import, because the generator modules read the row at import. A unit whose logic target is not under `Sources/` yet writes every file of its run under `out/<unit>/` at the same relative path and says so in one line, and `draftcheck.py` drafts its stems there and builds nothing. The header parse, the views, and the re-exports stay on the game target for a run of any unit.
- `fnsweep.py`: the function manifest for one module, from one unity parse.
- `symsweep.py`: the symbol manifest. It lists every macro constant, enum constant, and file-scope global a module references.
- `pass2lib.py`: the worktree scanner the two sweeps use to mark items as ported.
- `merge.py`: the second pass. It reads the `extract.py` trees, compares every declaration across modules and trees by code identity, and writes the C targets: `CJKAShared` for what MP and SP agree on, `CJKAMP` and `CJKASP` for what each tree's modules agree on, and `CJKAMP_Game`, `CJKAMP_CGame`, `CJKAMP_UI` and their SP twins for the rest. A type is shared only when everything it includes is shared. Each target is a SwiftPM C target: the umbrella, the module map, and the headers under `include/`, with the translation unit and `layout_asserts.h` beside it. `merge.py --out ../../Sources` writes the package's targets, and the default writes `out/merge/` for a dry run.
- `reexport.py`: the Swift re-exports. It parses each C target's umbrella and writes one Swift file per Raven header under the view target's `Generated` directory: a macro as a `public let` that reads the C value, an anonymous enum's enumerators as plain constants, a named enum as a struct with one static per enumerator, and a scalar typedef as a typealias. Swift's importer refuses a macro with an expression body and offers no way to ask which, so `--probe` builds, reads the failing lines, and moves each rejected name one rung up a ladder: the C body spelled as a Swift expression, the same expression narrowed to `Int32`, then a `TODO: Port` marker with the C text.
- `skeleton.py`: every function of the MP game module as a stub, one Swift file per Raven `.c` file under `Sources/JKAMP_GameLogic` and `Sources/JKAMP_BG`, in Raven's order, with Raven's block as a `/** */` comment, a `/// Source:` line, Raven's signature by the same table, and the marker pair of rule 14 as the body. Raven's `static` becomes `private`, and so does every copy of a name that more than one file defines, except a function the oracle stores in a callback field, which a thunk names. A bg function or file-scope variable that a game file names is `public`, because it crosses the module line. The second output is `Sources/JKAMP_GameLogic/Generated/Callbacks.swift`, one enum per callback field with one static thunk per stored function. A `.c` enum that `extract.py` leaves in its `.c` file because another `.c` file declares its names differently is `private let` constants at the top of the stub, read from the `file_enums` rows of `out/extract/mp-game/extract.json`. A stub file whose first line is no longer the generated header is adopted and left alone. `--only g_mover` prints one file. `--publish` puts `public` on the declarations the public rule names in the adopted bg files and changes no other text.
- `spelling.py`: the one owner of the Swift type a C type has. One question lives there: for this C type and this role, the field of a view, a parameter, a return, a local, or an expression, what is the Swift spelling, and which conversion crosses into it. It reads `SCALARS` and `NARROW` of `reexport.py` and the tables of `rulings.py`, and holds the shape rules over them. `table.py`, `views.py`, and `bodies.py` ask it and keep no branch of their own.
- `table.py`: the C-to-Swift table of `abi-stubs.md` row 2, shared by `traps.py` and `skeleton.py`. It gathers the sweep facts and the rulings of a cursor, hands them to `spelling.py`, and wraps the answer into the `Param` its callers read. A `char *` out-buffer is a returned `String` only in a trap. The table owns the facts about a function's locals the same way it owns the facts about its parameters. `Table.locals_of` gives them for one function, keyed by file stem, function, and name: which `char *` local walks a named buffer, which pointer local walks a table of records, and which names the body writes, writes once outside a loop, or takes the address of. The first read of a function computes the facts and every later read takes them from the store, so a generator that reads no body pays nothing. The cursor sweep leaves the body of every function behind for that read. The read carries the cursor sweep's rows forward instead of reading those stores again, and it asks `spelling.py` for the spelling of a local and holds no type branch of its own. `bodies.py` reads the result in one lookup and walks no body for it.
- `store.py`: the table cache of the sweeps, `table.sqlite` in WAL mode, outside version control. `Table.sweep()` loads the facts whose key matches and runs only the sweeps of a stale generation. A load is one read transaction, so a save from another run during the load cannot mix the rows of two saves. The base key covers every file the three parses read, the declared names and callback signatures of the generated declarations the views read, the tool modules `project.toml` lists, and the set of records with a view. The adoption key covers the base key and the first line of every stub, so a stub edit costs the store sweep alone. A stale generation names its changed files on standard error. `--rebuild` on a generator sweeps every generation again, and a deleted store file rebuilds on the next run. A run of `skeleton.py` or `manifest.py` also writes the signature rows that `lookup.py sig` and `lookup.py fn` read, as the `signatures` generation. Its key covers the adoption key and the hash of every stub the rows read, and the store keeps each stub hash. `lookup.py` rehashes those stubs alone, and on a mismatch it names the changed stubs on standard error, tells the user to run `skeleton.py`, and reads the manifests. The base generation also holds the syntax rows of every function body: `statements`, one row per statement in preorder with Raven's line and text, `comments`, and `macros`. The `lowered` generation holds the drafts. Its key covers the adoption key, the declaration lines of every Swift file under `Sources/`, and the modules `project.toml` lists under `lowering`, so a body edit under a signature keeps the key. `lowered` has one row per drafted statement with its form, and `lines` has one row per printed line with its statement, its role, its depth, and its text. A function lowers on its first read and saves its rows, and a change of the lowered key deletes every lowered row and line row. `rejected` holds the compile holes of the last draftcheck run under the lowered key, and a write keeps the rows of one key alone. `alignments` and `aligned_files` hold the line map of `align.py`. A reader command opens the store with `reader=True`, which writes nothing when the schema version matches, so the file keeps its bytes. On a store of another schema version, a reader open stops with one line that names the stored version, the version of the code, and `bodies.py`, and deletes nothing. A writer open deletes that store and makes it again.
- `tests/`: the unittest tests of the store, the key, the loader, lookup, the project file, the syntax rows, the roles, the lowered rows and the printer, `align.py`, and `compare.py`. Run `.venv/bin/python -m unittest discover -s tests`, and add `SLOW=1` for the tests on the real parse. Each SLOW test works on a copy of the store in a temporary folder.
- `tables.py`: Raven's data tables as C storage, written to `Sources/CJKAMP/bg_tables.c` for the bg tables and `Sources/CJKAMP_Game/g_tables.c` for the six game tables. It holds one piece per table, each naming the oracle file and the first and last line of Raven's text, and it copies those bytes as they stand, so a copied range keeps Raven's CRLF and the tool's own lines are LF. A piece with no line range carries the tool's own lines alone, which is how the offset-macro pragma and the `#undef` of `_JK2MP` stand beside the tables. It reads no parse, so it runs right after `merge.py`, before `check.sh` compiles the target. `--print` prints both files and writes nothing.
- `traps.py`: the typed trap functions, one per Raven `trap_*` in `g_syscalls.c`, written to `Sources/JKAMP_Game/Generated/g_syscalls.swift`. It reads the run's one parse and its one swept table, takes every function whose body is one `syscall(...)` call, and maps each parameter by the table of `abi-stubs.md` row 2 through the typed `Syscall.call` overload of the view target. The NULL sweep walks the game unit and the cgame unit, so a parameter is optional when a caller in either unit hands it NULL. A `char *` beside an `int` named as a size becomes a returned `String`, a `vec3_t` is passed by address inside `withUnsafePointer`, and a trap with a parameter or return the table cannot map is emitted with a `TODO: Port signature` marker, Raven's C text, and a `portMissing` body. `--only trap_Trace` prints one trap.
- `views.py`: the Swift views over Raven's structs, one file per view type under the view target's `Generated/Views` directory. It walks the closure of `gentity_t`, `gclient_t`, `level_locals_t`, and `playerState_t` by value, by array, and by pointer, and maps each field by `spelling.py`, which holds the table of `struct-views.md` row 2: a scalar as itself, `qboolean` as `Bool`, an enum as its re-exported struct, `vec3_t` as `SIMD3<Float>`, an array as a `Slots` over the field's address, `char *` as `PooledString?`, a nested struct and a struct pointer as views, and a stored function as its C type with a typealias per signature and a `run` method per field. A view in another module is built from its `OpaquePointer` handle, so no raw pointer crosses a module. A field with no table row gets a `TODO: Port` marker with the C text.
- `bodies.py`: a first Swift draft of each function body, translated statement by statement from Raven's AST and printed to standard output. It never writes into `Sources/`. The `Drafter` is the one entry and holds the state of a draft, and the `Registry` beside it reads the `inout` positions of every Swift function already under `Sources/`. The emit stands in five modules by concern, each one a set of methods the `Drafter` takes: `draft_statements.py` for the statement forms, `draft_expressions.py` for the expressions and the operators read from a token span, `draft_calls.py` for a call, its arguments, and the overload it takes, `draft_declarations.py` for the locals, the parameter copies, and the scratch closures, and `draft_classification.py` for the view, Slots, entity, and text questions the other four ask. `draft_classification.py` holds the `Hole` a Port-note stands under, so every concern reads it from one place. `--stem bg_pmove` prints every draft of one file, and `--only PM_AddTouchEnt` prints one. The drafter writes the lowered rows and the line rows of each function into the store, and `printer.py` prints the text from the line rows. A line row names the innermost statement whose draft holds it, so a line inside a labeled frame names the label and a line inside a scratch closure names the record local. `--compile-holes` prints each statement the last draftcheck run rejected as a compile hole.
- `draftcheck.py`: the compile gate of `bodies.py`. It splices the drafts of a Raven `.c` file over the hand bodies of its Swift file in a mirror of the package under `.build-draft/` and builds the game product there, so no file of the working tree changes. The report separates the holes the draft left, the cascade errors a hole caused, and the defects that stand on their own. `--stem bg_pmove` gates one file, `--stem bg_pmove,bg_misc` gates several in one invocation, `--all` gates every bg stem, `--game` every game stem, and `--every` both. A run parses and sweeps once, splices every stem into the mirror, and builds once per pass. Each error goes to the stem whose file the compiler names. A statement whose drafted line the compiler rejects is a compile hole on the next pass, by its file, its function, and its seq, and a stem with no such statement keeps its draft. After the last pass, each stem gets its own line, the mirror holds the hand text again, and a total line closes the run. The compile holes of the last pass go to the `rejected` table of the store. The command exits 1 when a defect stands.
- `printer.py`: the text of the drafts from the line rows, and the layout of the drafter's output. It indents a row by its depth, joins Raven's trailing comment onto its line, drops the module qualifiers of a body line, and prints the hole count of the stem as the footer. It never reorders a row. Its command prints from the store with no parse and no libclang: `--stem bg_pmove` prints one file, and `--only PM_AddTouchEnt` prints one function. It computes the lowered key again from the stubs, the Swift declaration lines, and the lowering modules, and takes the C-inputs part from the stored base key, because only a parse computes that part. A stale key, a missing function, or a function with no line rows stops the command with one line on standard error and exit 1. A stem whose stub the store lists and that holds no function prints the footer alone. `--compile-holes` prints the three lines of a compile hole in the place of each rejected statement. A rejected declaration, or a rejected statement that opens a scratch or choice closure, changes the draft of the statements after it, which the rows cannot show, so the printer stops on such a function and names `bodies.py --compile-holes`.
- `layout.py`: the indentation step, the Port-note line, and the compile note, which the lowering writes and the printer prints.
- `lowering_key.py`: the lowered key and the language of the lowered rows, which `bodies.py` computes from its parse and the readers compute with no parse.
- `snapshot.py`: the gate of a tool change. `--out <folder>` writes the text of every generator that reads the table, one file each: `skeleton.py` and `manifest.py` per stem, `traps.py`, `channel.py`, `views.py`, and `bodies.py --stem` per stem of the bg, game, and shared targets, so `align.py --adopted` finds the line rows of every adopted stem after a check. `--check <folder>` writes a new snapshot to a temporary folder and compares the two by `diff -r`, exit 0 when they are equal and 1 when a file differs. The snapshot folder belongs to the caller and stays outside version control.
- `align.py`: the line map between a hand file and the drafts of its Raven file, with no parse. A hand function and a draft function match by their `/// Source:` line, as draftcheck splices them, and difflib compares their stripped lines. An equal line is `same`, and a line of a replaced block of equal length on both sides is `edited`, each with the line row it matches. A line the hand wrote in place of no draft line is `hand`, and so is each line of a forward or of a hand function whose Source line no draft holds. A function whose body between its signature and its closing brace is still the TODO line and the `portMissing` marker of the skeleton is `stub`. Else a function whose ratio is under 0.3 is `rewritten`, and its name and ratio go to standard error with the count of draft lines no hand line matches. Every line of a `stub` or a `rewritten` function has no line row. The command skips a hand file whose hash and lowered key match the stored ones. `--stem bg_pmove` aligns one file, and `--adopted` aligns every stem whose stub is adopted. It exits 2 when the store or the line rows are missing or stale.
- `compare.py`: what a hand file changed against the draft. `--stem bg_pmove` prints each hand line in state `edited` or `hand`: Raven's file and line, the function, and the role, then a `draft:` line and a `hand:` line. A `rewritten` or a `stub` function prints one line with its Source line and no texts. `--counts` prints the count of each state for each function. `--against <folder>` compares the stored line rows of the stem with the draft file of a snapshot folder and prints each differing line with its C line. The command exits 0 when nothing differs, 1 when a line or a function differs, and 2 when the store, the alignment, or the snapshot is missing or stale.
- `extract.py`: the type copier. It writes one C header per Raven struct, union, enum, or typedef, with the oracle path mirrored, plus a constants file per Raven header, `forward.h`, `all.h`, and `layout_asserts.h` with the oracle's sizes and offsets. A declaration the parse cannot read is dropped, and so is a declaration that names one of its names. A file listed in `adopted.json` in the output directory is never overwritten. `extract.json` lists each `.c` enum whose names another `.c` file declares differently under `file_enums`, with each enumerator's initializer text, for `skeleton.py`.

## The placement rules

A type lands in the tree target, `CJKAMP` or `CJKASP`, when every module of the tree that emits it agrees on its text, or when one module alone emits it from a Raven header two or more modules see, because `usercmd_t` in `q_shared.h` belongs to every module and only the game's type closure holds it. A type from a header one module sees lands in that module's target. The bg run reads `q_shared.h`, `bg_public.h`, `bg_local.h`, and `bg_saga.h`, and never `g_local.h`, so the game-private types stay in the game target and the bg types in the tree target. A type both trees define identically lands in `CJKAShared`, and a macro identical in both trees is shared only when every name its body uses is shared too.

A `.c` file's own object-like macros, such as `MOVER_LOCKED` in `g_mover.c`, and its own enums, such as `TAUNT_*` in `g_active.c`, go to `<dir>/<stem>_c/constants.h` and are placed per module, never unioned, because `bg_misc.c` defines `MAX_POOL_SIZE` one way under `QAGAME` and another way in cgame. Two kinds stay in their `.c` file and are reported: a name a header uses as an identifier, such as Raven's `#define currentOrigin r.currentOrigin`, which would rewrite the header, and a name two `.c` files of one module define differently, which one header cannot carry. An enum also stays when a header, a hand header of `HAND_FILES`, or a `.c` macro names one of its names, and when another `.c` file declares one of its names in a different enum, as the NPC_AI files do with `LSTATE_NONE`. An enum two `.c` files declare alike is copied once.

## The layout check

`extract.py` parses each module once per target triple and writes `layout_asserts.h` as one block per ABI under a guard on Clang's `__SIZEOF_POINTER__` and `__SIZEOF_LONG__`. Three ABIs cover every triple: `ilp32` for the 32-bit targets, `llp64` for 64-bit Windows, and `lp64` for 64-bit Linux and Apple. `TRIPLES` in `extract.py` lists the triples and the ABI of each, and the writer exits when two triples of one ABI give different asserts, so a target that breaks the grouping shows up as a run that fails and not as a block that lies. `check.sh` compiles every target for every triple with `-ffreestanding`, so no SDK is needed for a foreign one. The merge exits when a seam type, or a record it holds by value, has two sizes across the ABIs of one pointer width. `--host-only` skips the foreign parses for a quick run.

## The gate of a tool change

A change to a tool module runs `snapshot.py --check` against a snapshot of the code before the change, and the change moves no printed byte unless it means to. A warm check reads the stored lowered rows, so it tests the lowered key as much as the drafter. Every module the drafter imports is in `[store] modules` or `[store] lowering` of `project.toml`. A drafter import outside the two lists would leave stale rows under an unchanged key, and the check would pass on them.

## Setup

```sh
cd tools/oracle-closure
python3 -m venv .venv
.venv/bin/pip install libclang==18.1.1
.venv/bin/python closure.py --list-modules
.venv/bin/python closure.py mp-game playerState_t --layout
.venv/bin/python extract.py mp-game
clang -fsyntax-only -x c -std=gnu11 -Wno-everything -I out/extract/mp-game -I glshim out/extract/mp-game/layout_asserts.h
.venv/bin/python merge.py --out ../../Sources
.venv/bin/python tables.py
./check.sh ../../Sources
.venv/bin/python reexport.py --probe
.venv/bin/python views.py
```

`check.sh` compiles every merged target's translation unit as C with its dependency include directories and exits nonzero on the first failure. Its one argument is the directory the merge wrote, `out/merge` by default. `EXTRACT_DEBUG=<TypeName>` makes `extract.py` print every include it adds for that type and why, for a dependency that looks wrong.

## Known gaps

The ported-status half of `fnsweep.py`, `symsweep.py`, and `pass2lib.py` scans Rust crates under `crates/`, and `symsweep.py` names a jka-rust worktree path. Those paths do not exist here. The oracle-side half of each script works unchanged. A later step points the ported-status scan at `Sources/`.
