# Oracle closure

`tools/oracle-closure/` is the tool suite that carries Raven's C into the Swift port. It is a transpiler with a judgment layer on top of it. Every answer it gives comes from one libclang parse of the oracle, with the compile flags of Raven's own Release configuration, so the tool states what the C compiler states and never a guess. `tools/oracle-closure/README.md` is the per-script reference, and this document holds the shape.

## 1. The pipeline

1. **The parse and the closure.** `closure.py` parses one module, alone or as a unity translation unit over every `.c` file of the module. `modules/<name>.py` holds the flags, the include roots, and the source files of that module. The header parse reads the entry list of the module. A spec with an `entry` field names the list, and the header parse reads that list. A spec without an `entry` field derives the list from its `srcglob` field: `closure.py` reads the include graph of the unity parse and lists each oracle header that a source file of the module includes, in order of first reach. The list keeps only its roots. A header that another header of the list reaches, and that does not reach that header back, stays out, because a header with no include guard, such as `g_local.h`, parses twice when the list names it beside a header that includes it. A header that the `exclude` field of the spec names stays out of the list too. `HEADER_PRELUDES` of `rulings.py` gives a header the text that a `.c` file writes before its include, as a line range of that `.c` file. The header parse writes that text before the include of the header, so the header parses as the `.c` file sees it, and the enum of the text stays in the constants file of its `.c` file. After the header parse, `extract.py` makes sure that the parse reaches every header of the list before the root filter, and it exits with the names of the headers that the parse does not reach. It answers three questions about a type or a function: its dependency closure, its by-value or pointer-only class, and its size and field offsets. Every other script reads this parse. `Parse` holds the translation units one run reads: the game unit, the cgame unit, and the view target's headers, each parsed one time. A `main()` builds this value and hands it to every generator, so a generator parses nothing of its own. Both unity parses carry the one overlay text of `overlay.py`, which declares Raven's function-like macros as functions, so every generator reads one parse shape.
2. **The C targets.** `extract.py` copies each kept declaration out of the oracle as a verbatim slice, one file per struct, union, enum, or typedef, with a constants file per Raven header and `layout_asserts.h` from the oracle's own numbers. A `.c` file's own macros and enums go to a constants file of that `.c` file, placed per module, and a name that header cannot carry stays in the `.c` file. `merge.py` compares the trees by code identity and partitions them into the SwiftPM C targets: `CJKAShared` for what MP and SP agree on, the tree targets, and a target per module for the rest. When two modules read a different text for one macro of a header, `merge.py` places the whole constants file of that header per module in the same way, and a header that every module reads the same keeps one placement for all modules. The umbrella of each target follows the `all.h` order of the modules, header by header, with the constants of a header before its types, which is Raven's include order. A prelude's `.c` constants file stands before the header of that prelude. `tables.py` writes `Sources/CJKAMP/bg_tables.c` after the merge, one piece per table, copying Raven's bytes for each line range as they stand. `check.sh` compiles each target for every triple.
3. **The re-exports.** `reexport.py` writes one Swift file per Raven header under a view target's `Generated` directory, so a logic target reaches Raven's macros, enums, and scalar typedefs without an import of C. `--probe` builds, reads the rejected names, and moves each one down a ladder of fallbacks.
4. **The table and the rulings.** `spelling.py` owns one question: for this C type and this role, the field of a view, a parameter, a return, a local, or an expression, what is the Swift spelling, and which conversion crosses into it. `table.py` gathers the sweep facts and the rulings of a cursor, hands them to `spelling.py`, and wraps the answer into the `Param` its callers read. `rulings.py` maps by name: which struct gets a view, which return is optional, which field is never NULL, which function is not ported and why. A shape rule is code, a name rule is data, and a name rule lands only by a ruling. A run sweeps one `Table` over the `Parse`, and `skeleton.py`, `traps.py`, `channel.py`, `manifest.py`, and `bodies.py` read the facts of that one sweep. The table owns the facts about a function's locals beside the facts about its parameters. `Table.locals_of` gives them for one function, computed on the first read of that function and held in memory for every later read, so a generator that reads no body pays nothing. The store is one `Local` per local, keyed by file stem, function, and name, beside the name sets of every write, every single write, and every address the body takes.
5. **The views.** `views.py` walks the closure of each root struct and writes one view per reached type. A view holds a pointer into engine-owned C memory and gives one Swift property per C field. A field's Swift type is `spelling.py`'s answer to the field role, and `views.py` writes the accessor over it. A fact about the C belongs to `table.py`, so `views.py` builds a `Table` over the generator it already holds, sweeps it once over the run's `Parse`, and reads the subscript sweep's field set from it. The set says which pointer field gets the second accessor of its view.
6. **The skeleton.** `skeleton.py` writes one Swift stub file per Raven `.c` file, in Raven's order, each function with Raven's comment block, a `/// Source:` line, the table's signature, and the marker pair of rule 14 as its body. It also writes the thunk namespaces, so a stored function keeps one address for the life of the module. A bg function or file-scope variable that a game file names is `public`, and `--publish` puts that keyword on those declarations in the adopted bg files and changes no other text. A game function that a Swift file of another source target calls is `public` too, `Com_Error` and `Com_Printf` for the shell's bg channel closures. A void function with no return statement whose last statement calls a function that returns `Never` also returns `Never`, so `G_Error` and `Com_Error` match the closure type of `bg.error`. A `.c` enum whose names another `.c` file declares differently is private constants at the top of its stub, and the skeleton reads the list of those enums from the `file_enums` rows `extract.py` writes into `extract.json`. A `void *` file-scope variable is an `OpaquePointer?` on the state object, the spelling the Ghoul2 traps take. A file-scope pointer that a body sets to a file-scope table of records is the `Int32` index of its slot, `pushed_pIndex` for `pushed_p`. A struct record whose initializer is all C's zero is a zeroed allocation of the storage class, not a data table. A data table of records that hold the address of a function or of a struct, `spawns` and `gameCvarTable`, is a hand array of `<View>Row` values on the state object, the stub forwards it under Raven's name, and `tables.py` writes no table for it.
7. **The traps and the channel.** `traps.py` writes one typed function per Raven `trap_*`, each one call through `Syscall.call`. A `NIL_OVERLOADS` entry of `rulings.py` gives a trap a second overload that takes the named view as optional. A trap's `const void *` parameter that Raven's callers hand a `char *` text gains an overload that takes a `String`. `channel.py` writes the bg channel of rule 23: one bare function per strap and per game callback, each forwarding to a closure the consumer installs.
8. **The manifest.** `manifest.py` writes one table per Raven `.c` file under `.claude/manifest/`, one row per function, with the oracle line range, the Swift stub line, the marker state, the jka-rust line range, and the table's current signature. `rosetta.py` writes the C to Swift type stones, and `lookup.py` answers one question against the stones and the manifests with no parse.
9. **The body drafts.** `bodies.py` translates a function body statement by statement from Raven's AST and prints the draft to standard output. It never writes into `Sources/`. The emit stands in five modules by concern, and the `Drafter` of `bodies.py` is their one entry: `draft_statements.py` for the statement forms, `draft_expressions.py` for the expressions and the operators read from a token span, `draft_calls.py` for a call, its arguments, and the overload it takes, `draft_declarations.py` for the locals, the parameter copies, and the scratch closures, and `draft_classification.py` for the view, Slots, entity, and text questions the other four ask. Each concern gives the `Drafter` a set of methods, the state of a draft lives in the `Drafter` alone, and `draft_classification.py` holds the `Hole` a Port-note stands under, so every concern reads it from one place. The drafter reads the local facts of the function from `Table.locals_of` and derives none of them by a walk of its own. A name in `HAND_MACROS` takes the Swift spelling of its entry, `buildDate` for the compiler's `__DATE__`, and a pointer walk over a hand table is a hole. A local whose shape the C alone does not give, a text local, a raw pointer local, and a local over a table of records, stays with the drafter, because each one asks the registry of already-written Swift what a callee returns or how a global is spelled.
10. **The compile gate.** `draftcheck.py` splices the drafts of one file into a mirror of the package under `.build-draft/` and builds the game product there. The working tree does not change. One invocation takes one stem, a comma-separated list of stems, `--all` for every bg stem, `--game` for every game stem, or `--every` for both. It parses and sweeps once for the whole run. Each stem drafts, splices, builds, and reports on its own line, the mirror holds the hand text of the stub again before the next stem builds, and a total line closes the run. A defect line names the file that the compiler names, so an error in a hand file such as `jampgame.swift` reads under that file and not under the file of the stem.

## 2. The layers

The analysis layer is language-independent. It holds the parse and the flags of `closure.py`, the dependency closure, the layout table of `extract.py`, the function and symbol sweeps of `fnsweep.py` and `symsweep.py` with their global read and write census, and the C-side reading of each statement in `bodies.py`. Its shape is the Visitor's: a walk over clang's cursor kinds, which rarely change, under operations that are added often. The dispatch is a branch on the kind, with no type of its own. `extract.py`'s `IfResolver` is the Interpreter of this layer. It holds the grammar of Raven's `#if` expressions and evaluates it, and one evaluator stands where the book puts one type per rule.

The emission layer is Swift-specific. `spelling.py` is its type table, `table.py` is the entry over it, and each `Param` carries the kind that picks the emission. The views and the re-exports are Adapters: the C struct and the C macro are the Adaptee, and the Swift property and the Swift `let` are the interface the caller expects. A generated trap is a Proxy of the book's remote kind, a local stand-in for a service in the engine's address space. A thunk adapts a Swift function onto a C function pointer field. The closures of the bg channel are one-method Strategies, and `installBgChannel()` binds them.

The per-project layer is `rulings.py` and the docket rulings behind it: the names, the signatures, and the exceptions that no C type alone decides.

The seam between analysis and emission is the parse, `closure.py`'s declaration map, and `extract.py`'s tree, none of which carries a Swift word. `spelling.py` is the first file above that line, and `table.py` sits on it. A second emitter for another language would replace `spelling.py`, `table.py`, and the writers above them, and would keep everything below. The book's Builder names that shape, one construction path and several representations. The suite holds one emitter, so its own form line reads "none", and the parts below the seam are the parse and the type tree in the estate's words.

`lookup.py` is the Facade over the generated stones and manifests, the one entry a blind transcriptor uses. `merge.py`'s partition to a fixed point, `draftcheck.py`'s mirror build, and `bodies.py`'s registry of `inout` positions match no pattern in the book. They are the partition, the gate, and the index in the estate's own words.

## 3. The judgment layer

The tool marks what it cannot decide instead of inventing an answer. A hole is that mark, and it has three parts: a Port-note that states what is missing, Raven's C text on a `// Raven wrote:` line, and a `portMissing` call that traps at run time. A draft with holes compiles as far as it goes, and one grep lists every hole by its Raven subject.

A cascade is a compile error that follows from a hole, because the hole swallowed the declaration of a local that later lines read. A defect is a compile error that stands on its own, which means the draft translated something wrongly. `draftcheck.py` reports the three counts apart, so the holes measure the work left and the defects measure the tool. The compile gate is the proof. A draft that builds in the mirror carries no defect the Swift compiler can see, and the port's own gate, `swift build`, `swift build -c release`, and `swift test --no-parallel`, is the same proof one level up. The gate reads errors only. A warning stands when it maps to a line Raven wrote, a dropped call result, a local never reassigned, a branch under `if (0)`, an unread store, or a NULL test on a value. The round's report counts each such warning without failing the gate on it. No body line changes only to silence a warning.

## 4. The invariants

- `oracle/` is read-only. Every script reads it and no script writes into it. A Windows-style include path is shadowed in memory, and the file on disk keeps Raven's text.
- A `Generated/` directory is regenerated whole and is never edited by hand. Each file there carries its note and the rule it serves.
- An adopted stub is left alone. A stub becomes adopted when its generated header line is deleted, and the generator then reports it instead of writing over the port.
- The rulings hold the names. A generator reads `rulings.py` and never invents a name, a shape, or an exception of its own.
