# Porting Rules

Rules for converting Raven's C and C++ under `oracle/` into Swift. The rules were copied from `jka-rust/docs/porting-rules.md` and walked row by row on 2026-09-08. Each row below is the ratified text. A port is verified against the oracle differentially: the committed golden fixtures from jka-rust's oracle harnesses and jka-rust's lockstep referee, which runs Raven's compiled module and ours side by side.

## A. What "correct" means

1. **Behavioral parity at the ABI seam, verified against the oracle.** A port is done when its observable behavior matches the oracle under differential test: the committed golden fixtures and jka-rust's lockstep referee. Internals are free. The seam is not.
2. **No speculative behavior.** If Raven's behavior is unclear, port it faithfully first, even if ugly. Get it green, then refactor behind the passing diff. Never guess a cleaner behavior.

## B. State

3. **No hidden globals.** Raven's `level`, `g_entities`, `gclients`, cvar tables, and engine singletons do not become scattered Swift globals. All module state belongs to one `final class GameWorld` in `g_local.swift`, and exactly one `nonisolated(unsafe) let world` instance exists in the logic target, because `vmMain` has no context argument and the engine calls the module from one thread. Every Raven global is a computed property over that instance, declared in `g_local.swift` and nowhere else, so ported bodies keep Raven's spellings, and functions stay bare functions. ABI-crossing state such as the entity and client tables lives in C memory the world owns, with Raven's stride, and Swift reaches it through pointer-backed view structs with `nonmutating` setters, one view type per file. The views target is the only Swift target that imports a C types module, with `internal import`, because the C headers declare Raven's functions and a bare Swift function of the same name collides with the import. A view crosses the C function pointer boundary as an `OpaquePointer` handle, and a function stored in a `think`, `use`, `touch`, `pain`, or `die` field has the C shape and makes its view on its first line. The world owns the string pool that `char *` fields point into. Tests reset `world` and run serially. No actor guards the world. A mod that needs concurrency wraps the world in its own actor.
4. **State is reached through one name, not threaded.** Ported functions stay bare and read `level`, `g_entities`, and the other Raven globals as computed properties over the one `world` instance, so no function carries a world parameter. The entry points in the shell target call the bare functions directly. A function that a test drives on its own state constructs a `GameWorld` and assigns it to `world` first.
5. **Entities are views, not pointers and not indices.** A function that Raven gave a `gentity_t *` takes an `Entity`, the view struct over one slot in the C table. The view holds the slot pointer, so copying a view copies the pointer and not the entity, and two views of one slot compare equal. A pointer field such as `enemy` or `parent` reads and writes as `Entity?`. The raw pointer never appears outside the view target. An index appears only where Raven used one, such as `s.number` and the `entityList` a trace fills.
6. **One owned instance per logical singleton.** Raven had two true globals in a module, the engine's syscall entry and the module's own state, and each is one instance behind one name: `Syscall.entry` in `JKAShared` and `world` in the logic target. No other static exists. A subsystem that Raven wrote as file-scope statics, such as the bot library's tables or the saber move tables, becomes a stored property of `GameWorld` or a `let` constant, never a new global.

## C. C to Swift idiom translation

Mechanical defaults below. Specific renames and per-type idiom choices are decided when that code is ported, not here.

7. **Out-params and `qboolean`.** Out-params become return values, a tuple when Raven filled more than one. `qboolean` becomes `Bool` at every Swift surface, and a view converts it at the C field. A function that returns an error code becomes a throwing function only where Raven's callers checked the code. Where they ignored it, the return is dropped.
8. **Macros, enums, and function pointer tables.** A `#define` constant stays a C macro in the copied header, and Swift imports it as a constant of the type Clang infers. It becomes a Swift `let` only where Clang cannot import it, such as a macro that names another macro in an expression. A Raven enum stays a C enum in the copied header and imports as a Swift struct with static members. The view target re-exports each constant and enum as a generated public Swift declaration, so logic targets never import a C module. A function pointer table, such as the `bg_*` weapon and saber tables, becomes an array of a Swift enum with one case per Raven function, dispatched by a switch, so no table holds a closure. The stored function pointer fields on `gentity_t` are the exception ruled in rule 3, and they keep the C shape.
9. **Manual allocation becomes ownership.** Memory the engine reads keeps Raven's shape: the entity and client tables and any buffer handed to a trap are C allocations the world owns and frees in one place. `G_Alloc` stays a bump pool over `memoryPool` and `allocPoint` on the world, with Raven's size and overflow error, because `g_debugAlloc` prints its accounting through `trap_Print` and the referee compares that stream. `G_NewString` goes away. The strings it made live in the world's string pool, which hands out stable C pointers for the `char *` fields the engine can read, and the ICARUS `parms_t` block is the pool's only other consumer. `String_Alloc` and `BG_Alloc` become owned tables the same way. Memory only the module reads becomes a Swift `Array`, `String`, or struct held by the world.
10. **Preserve control-flow behavior, not control-flow shape.** A C `goto` or early return may become a `guard`, a labeled `break`, or a nested function, as long as the differential test stays green. Raven's evaluation order is behavior where it touches a trap or a shared field, so a reordered call that changes the syscall stream is a divergence, not a reshaping.

## D. The ABI seam

11. **Pointer code is confined to three places.** The choke point is `Syscall.call` over the `SyscallTransport` protocol in `JKAShared`, whose engine conformer is the C shim and whose test conformer is a recorder. The typed trap functions, one per Raven `trap_*` with Raven's name, take views and Swift values, do the word packing, and live in the view target of their module, `JKAMP_Game` for `g_syscalls.c`. The view targets are the memory side, where `UnsafeMutablePointer` reaches into the C tables. The shell's `vmMain` decodes words into typed arguments and calls the bare function. The wire enums come from the copied `g_public.h`, and no per-syscall type exists. A logic target holds no `Unsafe` type, no `withUnsafe` call, no `unsafeBitCast`, and no word packing. The one exception is the `OpaquePointer` handle a stored think function receives, which it turns into a view on its first line. This rule may be reopened when the shell lands and the layout is visible.
12. **ABI-crossing types keep exact layout.** They are the C headers `extract.py` copies from the oracle and `merge.py` partitions, with Raven's names, order, and comments, and each target compiles `layout_asserts.h` with the oracle's `sizeof` and `offsetof` for every record on every build. A copied header is never edited. A port that changes a private type's shape does so in Swift, and the C field goes unused, so the merge regenerates every header and every assert whole on every run. A seam type, one the engine dereferences, has one size on every triple of the same pointer width, because Raven's `sharedEntity_t` holds pointers. Internal-only state gets idiomatic Swift shape and naming behind the views.

## E. Process

13. **Skeleton first, then bodies by file.** Everything the oracle states mechanically is generated whole and regenerated whole: the copied headers, the layout asserts, the constant and enum re-exports, the typed trap functions, the view accessors, and a Swift skeleton with every function of the module as a stub that carries Raven's signature, Raven's comment, a `Source:` line, and a body that traps with its Raven subject. Swift files mirror Raven's `.c` files in name and order. A generated file is adopted the first time a hand edit is needed. Bodies are ported file by file, in the order a live engine call needs them, and a body may call a stub. A signature the generator could not map carries a `TODO: Port signature` marker with the C text.
14. **Unported work is explicit, never a silent fake.** The marker is always `// TODO: Port <subject>`, where the subject is the exact Raven identifier, on its own line, with a space after the slashes so it matches the house comment form. An executable placeholder also calls `portMissing("<subject>", source: "<cite>")`, which traps with `TODO: Port <subject>` in the message. The generator emits both lines together, and a body port removes both together. A placeholder field or constant carries the marker alone. The `/// Source:` line above the declaration is the cite, so the marker carries none of its own. A deliberately callable no-op is rare, carries the marker and a one-line reason, and is a ruling of the user's. `grep -rn "TODO: Port"` lists every open item by its Raven subject, the count per file is the work left in that file, and nothing else spells unported work.
15. **Green at every commit.** `swift build`, `swift build -c release`, and `swift test` pass, and `check.sh` passes for the generated headers. Anything wired live matches the oracle under its differential test before the commit lands, so a referee divergence bisects to one commit. A commit ports bodies from one file, and a large file takes several commits, each leaving stubs for the bodies not yet ported. A signature change to a stub is its own commit, ahead of the body that needed it. A generator run is its own commit, so a diff is one kind of change.
16. **The stopping point.** A step ends when a real engine call works end to end and matches the oracle, not when a count of files is done. The engine for the proof is jka-rust's `mp_app` until the ILP32 build exists, because retail `jamp` cannot load a 64-bit module. The proof of a game module step is the lockstep referee green across the frames the step claims, and the proof of a `bg` or `q_math` step is its golden fixtures byte for byte.

## F. C++ track

Raven's C++ classes cross the ABI seam only behind pointers and handles, so their layout is free and they are reimplemented, never copied byte for byte.

17. **Design before transcription.** The list of what the track covers is measured, not guessed: it is each target's `cxx_only.txt`, the classes and the types that hold one by value. Decide a subsystem's Swift shape once. A closed virtual hierarchy becomes an enum with a switch, or a protocol with one conforming struct per Raven class where the set is open. An interface class becomes the handle it hides, a view when the storage is a C table and a Swift struct when it is not. Intrusive lists, pools, and `std::` members become `Array`, `Dictionary`, and `String` held by the world. Then transcribe the methods into that shape.
18. **Parity is proven differentially.** The oracle dumpers and their committed goldens come from jka-rust's `tools/*-oracle` harnesses unchanged, because they compile the unmodified oracle and the oracle is the same commit. The Swift port reproduces each golden byte for byte in a Swift test that reads the committed files, so `swift test` needs no C toolchain and no oracle checkout. A new subsystem that jka-rust never dumped gets its own harness under `tools/<subsystem>-oracle/`, in the same shape. Every float compares as its bit pattern.
19. **Diverge only where Raven's behavior is undefined:** a buffer overrun, a null dereference, a read of uninitialized memory. Pick the one defined behavior, note it in at most two lines at the site, and keep the case out of the shared fixtures or normalize it in the dumper with a comment. A Swift trap on an out-of-range index is a divergence of this kind when Raven read past the end, and the note says what Raven read.
20. **Preserve emergent per-mode quirks and drop dead surface.** MP first, SP as the diff. Duplicate, do not unify, even for accidental behavior. The merge's shared target is the one measured exception: a type both trees define identically is one type, and the merge proves the identity on every run. A function with zero callers in either tree is left as its generated stub with a `TODO: Port` marker and a one-line note that it is dead, so the skeleton stays complete and the marker count says what was skipped on purpose.
21. **House comment style throughout,** as `docs/style.md` states it. One Raven class per file on the C++ track, with private helpers in the same file, and the file cites both the class definition lines and each method's source lines. On the C track, one Raven `.c` file per Swift file, as rule 13 says.

## Comment and source-reference rules

Preserve Raven's comments. The generated headers keep them verbatim, the skeleton generator emits the comment block Raven placed above each function verbatim as a `/** */` doc comment above the stub, and a ported body keeps the comments inside the function. A Raven comment is quoted source, never reflowed and never linted. Every generated and every ported item carries a `/// Source:` line in the form `oracle/codemp/game/g_mover.c:1226` directly above its declaration, beneath any Raven block, so the two form one DocC entry, and a shared type carries one line per tree. State the conclusion, not the derivation. Add rationale only where a Swift choice diverges from the obvious, and cap it at two lines. A hand edit after adoption keeps the Raven block and the `Source:` line.

Raven's block is `/** */` and ours is `///`, so a reader can tell the two authors apart without reading.

```swift
/**QUAKED func_door (0 .5 .8) ? START_OPEN x CRUSHER
TOGGLE		wait in both the start and end states for a trigger event.
"angle"		determines the opening direction
*/
/// Source: oracle/codemp/game/g_mover.c:1226
func SP_func_door(_ ent: Entity) {
    // TODO: Port SP_func_door
    portMissing("SP_func_door", source: "oracle/codemp/game/g_mover.c:1226")
}
```

## Import and path style

Every `import` sits at the top of the file, and a logic file imports its view target and nothing from C. A symbol is referenced by its short name, never module-qualified in an expression, so `G_Damage` and `level` read as Raven wrote them. A module qualifier appears only to break a genuine ambiguity, and that case gets a one-line comment. Test files are exempt and may qualify freely.
