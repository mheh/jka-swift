# Transcription

This is the working guide for the agents that port Raven's C into the Swift stubs.
A transcriptor and a reviewer are blind transcriptors: they apply the shapes below and never design.
`docs/porting-rules.md` and its ratified rulings bind. Where this guide and a rule disagree, the rule wins.

## 1. The roles

A transcriptor takes one manifest file under `.claude/manifest/<stem>.md`.
The manifest lists each function of one oracle file, with its oracle line range, its Swift stub location, and its jka-rust line range.
The transcriptor's first edit is to delete the generated header line at the top of its Swift file, the `// Generated by tools/oracle-closure/skeleton.py ... Do not edit until adopted.` line and the blank line after it, which adopts the file so a later generator run never overwrites the port.
The transcriptor reads each function's oracle slice by that line range and ports it into the Swift stub at the listed line.
It reads the oracle only. It never reads jka-rust. The port carries Raven's behavior, not jka-rust's.

A reviewer runs after all transcriptors of a batch finish. It takes one file.
For each function it reads the oracle slice, the jka-rust slice from the manifest, and the Swift body, and confirms the three agree. The reviewer fixes what this guide settles. It notes the rest as a Port-note.

Both roles are per file and per assigned block. Neither touches another file.
A batch runs ten or more files in parallel.

### The read set

Ruling of 2026-09-09. A transcriptor reads exactly this set, and nothing else:

- the oracle slice for the row it is porting, by the manifest's line range
- its own Swift stub file
- its manifest
- the state file of its target, `Sources/JKAMP_BG/bg_local.swift` or `Sources/JKAMP_GameLogic/g_local.swift`
- the lookup tool

The lookup tool is `tools/oracle-closure/lookup.py`, the only command a transcriptor runs from the repository root.

- `python3 tools/oracle-closure/lookup.py <C type>` gives the Swift view and every field.
- `python3 tools/oracle-closure/lookup.py <C type> <field>` gives one field.
- `python3 tools/oracle-closure/lookup.py <typedef or enum>` gives a scalar or enum spelling.
- `python3 tools/oracle-closure/lookup.py fn <name>` gives a function's manifest row, with its oracle range, its Swift stub line, and its state.
- `python3 tools/oracle-closure/lookup.py sig <name>` gives the signature the table gives the function today. An adopted file keeps its old stub line, so a second pass takes the parameter list from this command and not from the file.

Unknown types become Port-notes.
A reviewer reads the same set, plus the jka-rust range from the manifest.
That range names a file of the submodule `jka-rust/` at the repository root, pinned at the commit whose `crates/mp/game/src` layout the manifest cites.
The reviewer reads that range in the submodule and never in the sibling clone `../jka-rust`, whose later layout holds the game functions as stubs.

Neither role greps across `Sources/`.
When a needed fact sits outside the read set, the agent writes a Port-note and moves on.

### The brief

Every transcriptor, reviewer, and sweep brief carries the house-style and asd-ste100 invoke lines at the start. Every sentence the agent writes itself, a Port-note, a comment, or a doc line, follows both. Raven's own comments are copied as written and are exempt.

## 2. The Port-note

A Port-note is the one way to raise a problem.
It is a comment directly above the affected line, in this form:

```swift
// Port-note: <what is missing or uncertain>
```

Place it above the function when the whole function is in doubt.

A function the transcriptor cannot port keeps its `// TODO: Port` marker and its `portMissing` body, and gains a Port-note above them.
A function ported with a doubt gets its real body and a Port-note.
A Port-note that names a behavior the body does not reproduce has a `portMissing` call on the line under it, so a grep for `portMissing` finds it and the drafter counts it as a hole.

`grep -rn "Port-note:" Sources/` is the docket. The user rules on it after a batch.
No question files. No messages to the user mid-batch. No invention to close a gap.

## 3. The shapes

### The stub's signature

The signature is kept as generated. Row 6 of step 2 already applied the pure-math case in `JKAShared`.
A transcriptor does not rename a parameter, reorder one, or change a return type, even where the C source suggests a cleaner shape.
The signature keeps the spelling of the tables below, `JKAShared.vec3_t`, and a body line reads every type by its short name, `vec3_t`, under the short-name rule of docs/porting-rules.md.
The zero vector is `vec3_t()`, and a vector with values is `vec3_t(x, y, z)`.

A name rule lives in `tools/oracle-closure/rulings.py`, in the tables `ROOTS`, `NEVER_NULL`, `TYPES`, `RETURNS`, and `PARAMS`.
A shape rule is code in `table.py`.
A function or parameter whose C type alone does not say its Swift shape has an entry in one of the `rulings.py` tables.

A struct a header declares that no root reaches joins `ROOTS` in `rulings.py`, so it gets a view.
A struct Raven defines inside a `.c` file has its definition copied as Raven wrote it, with a `// Source:` cite, into a hand header the target's umbrella includes.
An enum Raven declares inside a `.c` file goes to the constants header of that `.c` file through `extract.py`, and `reexport.py` emits its enumerators.
The enum stays in its `.c` file when a header, a hand header, or a `.c` macro names one of its names, or when another `.c` file declares one of them in a different enum, such as `LSTATE_NONE` of the NPC_AI files.
An enum of that last kind is `private let` constants of type `Int32` at the top of its stub, in Raven's order with Raven's values, under the enum's `/// Source:` line, and an enumerator with no initializer counts on from the one before, from 0 for the first.
`Sources/CJKAMP_Game/include/g_types.h` is this hand header for the game target, so a view can bind over the struct.

`text_offset` marks a pointer into the argument or `NULL`, such as `Q_strrchr`, and it returns `Int32?`.
`text_offset_nonnull` marks the same shape with no `NULL` case, such as `COM_SkipPath`, and it returns `Int32`.
`SkipWhitespace` takes the cursor by value and returns it advanced.
It has PARAMS kind `text_cursor` and RETURNS kind `text_cursor`.

A parameter no site of its body indexes keeps the one-record spelling, because a pointer the sweep cannot read is one record.
A PARAMS row wins over the sweep, so `table` still names the shape where a row names it.
A caller of a `Slots` parameter passes the `Slots` it holds, or the storage table under Raven's name.
A caller that holds one record's view has no `Slots` over that one record, and that call site keeps a hole which names the shape.

A proof over callers covers the game unit and the cgame unit, the two units the port parses.
The ui unit is outside every caller proof, because no ui parse exists, and no sweep guesses at a ui call site.
The cgame parse compiles `ui_shared.c`, and every sweep skips it, because the file is in the ui folder.

A trap's array of struct pointers is a storage table's base, and it keeps its marker under the PARAMS kind `pointer_array`.

A body that hands that trap a `char buf[N]` copies the returned text into the buffer, `strcpy(&arg, trap_Argv(1, Int32(arg.count)))`, so the buffer keeps its N bytes.
A test that is one call to a trap that returns `(Bool, String)`, `if (!trap_GetEntityToken(com_token, sizeof(com_token)))`, puts the call and the copy before the `if`, and the `if` tests the Bool.
An assignment from a trap that returns `(Int32, String)` takes the count from the first value and copies the text into the buffer with `strcpy`, so the buffer keeps its N bytes too.
A trap's `int *` parameter with a count beside it is an `inout [Int32]` the engine fills, `trap_EntitiesInBox(mins, maxs, &entityList, MAX_GENTITIES)`.
A function that hands its own `int *` parameter to that trap parameter takes an `inout [Int32]` too, such as `NPC_GetEntsNearBolt`.
A trap that fills a NUL-separated list, `trap_FS_GetFileList`, returns the whole buffer as a `CharBuf` in place of the `String`, and the body walks it with a `TextCursor` as Raven walked the bytes.
A buffer the engine fills with no size beside it has a PARAMS entry `("fill_buffer", capacity)`, with the capacity Raven's callers declare for it, and the trap returns the `String` the same way a sized buffer does.
A trap no file of the module calls, such as `trap_UnifyWhiteSpaces` and `trap_AAS_TraceAreas`, is a NOT_PORTED entry with that reason, and its shape is ruled when a module that calls it is generated.
A raw block the engine keeps, such as `trap_SV_RegisterSharedMemory`, has a PARAMS entry `raw` and is `UnsafeMutableRawPointer`.
A trap's `void *` parameter is an `OpaquePointer?`, and it gains a second overload that takes `inout CharBuf` when Raven's own callers fill it with a `char buf[N]`.
The overload hands the engine the buffer's base inside the generated file, so a body writes `trap_FS_Read(&BGPAFtext, len, f)` and a caller that holds a raw allocation keeps the first overload.
A trap's `const void *` parameter gains an overload that takes a `String` when Raven's own callers hand it a `char *` text, so a body writes `trap_FS_Write(str, strlen(str), fh)`.
A `NIL_OVERLOADS` entry of `rulings.py` gives a trap a second overload that takes the named view as optional, so `trap_Cvar_Register` registers the three NULL rows of `gameCvarTable`.

A record's `char name[N]` field that Raven passes as a write target to a non-const `char *` parameter crosses as an `inout CharBuf` the same way.
`views.py` writes a second accessor named `nameBuffer` beside the field's `String`, a `CharBuf` var whose getter copies the field's bytes out and whose setter puts them back, so a body writes `BG_SiegeGetPairedValue(&classInfo, "description", &descBuffer!.descBuffer)`.
The `String` accessor stays for a read of the text, and `strcpy`, `Com_sprintf`, and the rest of the buffer writers take the `Buffer` spelling.
Raven's `memset(ent->name, 0, sizeof(ent->name))` over that field is `ent.nameBuffer.zero()`, the `CharBuf` zero-fill, which the getter and the setter of the accessor carry back into C memory.
The rule holds for a zero value and the size of the same field.
Raven's `memset(buf, 0, sizeof(buf))` over a `char buf[N]` local or file-scope buffer is `buf.zero()`, because the buffer is a `CharBuf` of N bytes.
The size can also be the bound constant that the declaration spells, `AWARDS_MSG_LENGTH` for `char buf1[AWARDS_MSG_LENGTH]`, or an integer literal of N.
A memset over a whole array of scalars or vectors is `fill(_:)` on the `Slots` or the `Array` that holds it, one value into every element: `totalDmg.fill(0)`, `dmgDir.fill(vec3_t())`, `pVeh.m_iExhaustTag.fill(-1)`.
The size is `sizeof` of the array, or `sizeof` of one element times the declared bound, `sizeof( int ) * MAX_VEHICLE_EXHAUSTS`.
The value is zero for any element, `false` for a `qboolean` element, and -1 for an integer element, because every byte 0xff of an `int` is -1 again.
A two-dimensional array of scalars takes the same call, `G_WeaponLogPickups.fill(0)`, which fills every row.
A memset of zero over a whole record local drops, because the scratch slot is zero at entry, only where the target is the record itself and not a pointer to one, the size is the record's own, and no loop encloses the call. Otherwise it is the view's `clear()`.
The record's own size is `sizeof` of the record, of the pointee, or of the pointee's type name under any typedef, so `memset(*pVeh, 0, sizeof(Vehicle_t))` through a `Vehicle_t *` is `pVeh.clear()`.
A memset over a partial size keeps its Port-note, `memset(buff, 0, MAX_STRING_CHARS)` over the `char buff[MAX_STRING_CHARS*4]` of `BuildShaderStateConfig` among them.
A memset with a value the rules above do not give, or over a record with no view, keeps its Port-note too.

Raven's struct of eight bytes exists because the compilers of the time had no portable 64-bit integer.
Only the byte-swap pair touches `qint64`, and a body swaps with `byteSwapped`.
Raven takes the address of a const scalar to reinterpret the bytes, and a body reads `bitPattern`.

A pointer to one vector, such as `vec4_t *c` of `COM_ParseVec4` where Raven writes `(*c)[i]`, is `inout` too.

Raven passes one variable to two `inout` parameters of one call, as in `PM_ClipVelocity(v, n, v)`, and Swift refuses that call.
The draft copies each earlier argument into a local, `var vIn0 = v`, and passes the copy, under a comment that names the variable.
The callee reads the earlier arguments and writes the last.
For a call inside an `if` test, the copy and its comment are statements before the `if`.
A member path passed twice, `PM_ClipVelocity(pm->ps->velocity, n, pm->ps->velocity)`, goes through a view's setter, and Swift writes the unchanged in-copy back last.
So the last argument also takes a copy, `var velocityOut2 = ps.velocity`, and `ps.velocity = velocityOut2` is the statement after the call.
A member path passed twice inside a test keeps its hole, because the write-back has no line after the test.
A call inside a `while`, `do`-`while`, or `for` test keeps its hole, because one copy before the loop has a stale value from the second pass.
The copy replaces only the argument it copies, which the draft finds by its extent in Raven's file and its position in the call.
A different argument at that position in a nested or sibling call keeps its own text.

The returned value of a function-pointer return goes nowhere but into the view's stored function, and `ent.pain = NPC_PainFunc(ent)` reads as Raven wrote it.

A trap copies a `[JKAShared.vec3_t]` parameter into a flat `[Float]` of three per vector before the syscall, because `SIMD3<Float>` strides 16 bytes and Raven's `vec3_t` is 12.

The body of a `float *` return out of a static ring of temporaries is `vec3_t(x, y, z)`.

The text sweep reads a non-const `char *` parameter as a `String` when every use is a read.
A read is a pass to a `const` position, to a function of `TEXT_READERS`, or past the last declared parameter as a format argument.
A pass to a function whose body the sweep has and whose matching parameter the sweep reads as a `String` is a read too.
So are a comparison or a NULL test, the whole condition of an `if`, a `while`, a `do`, or a `?:`, and an indexed read or a dereference used as a value and not as a store target, `saberName[0]` or `*from`.
A pointer local set from the parameter, `p = from`, reads when each of its own uses reads, and a step of that local, `p++`, moves the local and writes no byte.
A parameter the body writes, steps, casts, or passes to a function with no body keeps the `inout CharBuf`.
A caller with a `String` for that parameter passes `var buf = CharBuf(name)` and `&buf`, and reads `String(buf)` after the call where Raven reads the result.
When Raven writes into a slot with room past the text, the buffer takes the size of the slot, and the text stores back into the slot after the call.

### Vectors and the vector macros

`vec3_t` is `SIMD3<Float>`, defined at `Sources/JKAShared/Views/Vectors.swift`.
`vec4_t` is `SIMD4<Float>`.

Raven's vector macros become operators or the ported `q_math` functions in `Sources/JKAShared/q_math.swift`:

| Raven | Swift |
|---|---|
| `VectorAdd(a, b, c)` | `c = a + b`, or `_VectorAdd(a, b, &c)` |
| `VectorSubtract(a, b, c)` | `c = a - b`, or `_VectorSubtract(a, b, &c)` |
| `VectorScale(a, s, b)` | `b = a * s`, or `_VectorScale(a, s, &b)` |
| `VectorCopy(a, b)` | `b = a` |
| `VectorMA(a, s, b, c)` | `_VectorMA(a, s, b, &c)` |
| `VectorNegate(a, b)` | `b = -a` |
| `VectorClear(a)` | `a = vec3_t()` |
| `VectorSet(a, x, y, z)` | `a = vec3_t(x, y, z)` |
| `DotProduct(a, b)` | `_DotProduct(a, b)` |

`ANGLE2SHORT` and `SHORT2ANGLE` are functions in `q_math.swift`, beside `SnapVector`.

A reduction such as `DotProduct` always uses the ported function, never a SIMD sum.
A SIMD sum may reassociate the terms, and that changes the float bit pattern the oracle produced.
`_DotProduct` at `Sources/JKAShared/q_math.swift:868` keeps Raven's scalar order for this reason:

```swift
/// A SIMD reduction may reassociate, so the sum keeps Raven's scalar order.
/// Source: oracle/codemp/game/q_math.c:1221
public func _DotProduct(_ v1: vec3_t, _ v2: vec3_t) -> vec_t {
    v1[0] * v2[0] + v1[1] * v2[1] + v1[2] * v2[2]
}
```

### A macro inside a `.c` file

An object-like macro Raven wrote inside a `.c` file is a constant of that file, and its stub carries it as a file-scope `let` at Raven's line, `let MAX_DISTANCE = 128 as Int32`, `private` where another file defines the name with its own value.
A literal Raven wrote with `f` is a `Float`, and one without is a `Double`, C's types.
A macro over the same file's names is a `let` over them, `let MAX_DISTANCE_SQR = (MAX_DISTANCE * MAX_DISTANCE)`.

### Primitive types

`qboolean` is `Bool`. `int` is `Int32`. `float` is `Float`.
A C integer narrower than `int`, a `short`, an `unsigned short`, a `signed char`, or an `unsigned char`, is `Int32` as a view's scalar field, a parameter, and a return, because C widens it to `int` at every read.
The view's getter widens and its setter stores the truncation C performs, and the C struct keeps Raven's type.
A fixed array of a narrow type keeps its element type.
A local of a narrow type keeps its storage, `var temp: Int16`, because the local is the one place C's truncation is a stored value.
A store into it truncates, `temp = Int16(truncatingIfNeeded: cmd.angles[i] + ps.delta_angles[i])`, and a read of it widens, `Int32(temp)`, as C does.
The arithmetic of a generator or a hash, `Q_rand`, `rand`, `irand`, `flrand`, and the others `WRAPPING_ARITHMETIC` of `rulings.py` names, wraps at 32 bits with `&+`, `&-`, and `&*`, as C's does.
An array index is the C constant or variable Raven wrote, for example `vec[YAW]` and `ps.stats[STAT_HEALTH]`, never `Int(...)`. Every array in the port takes any C integer index.
A slice index is the slice's start index plus Raven's index, `infos[infos.startIndex + count]`, and the `+` of `Sources/JKAShared/Views/Int32Indexing.swift` takes any C integer on the right.
A C enum is an `Int32` typealias, and each case is a bare `Int32` constant with Raven's name.
A body compares, stores, switches, and shifts it exactly as Raven wrote it. `.rawValue` and `EnumName(rawValue:)` never appear.
An unsigned hex mask Raven applies to an `int`, such as `0xfffffffc`, is spelled as the complement of the low bits, `~0x0000_0003`, the same bit pattern with no cast, and one comment line at the site says what Raven wrote.

A cast Raven wrote explicitly stays on the page, so `(int)v[0]` is `Int32(v[0])` and `(float)x` is `Float(x)`. A body never adds a cast Raven did not write.
`Sources/JKAShared/Promotion.swift` defines the arithmetic and comparison operators between `Int32` and `Float`, both orders, and the compound assignments, and each one promotes the integer as C does.
So `ps.velocity[2] -= ps.gravity * bg.pml.frametime` and `ps.origin[2] + MINS_Z + 1` are Raven's lines.
Swift reads `0.1` beside a `Float` as a `Float`, which changes the bits Raven's double math sets.
So a body writes `Double(...)` on each operand at the operator where it meets the double operand, and `Float(...)` once at the store, `drop += Float(Double(speed) * 0.1 * Double(bg.pml.frametime))`, and `(150 + pml.frametime) * 0.003` is `Double(150 + pml.frametime) * 0.003`, because C adds in float.
A macro constant that expands to a double literal, `M_PI` or `ARMOR_PROTECTION`, is a double literal, and a comparison or a cast whose operand C computes in double takes the same widening, `abs(Double(du0)) < EPSILON`.
A C library call that takes and returns `double` inside that expression takes its arguments in `Double` too, `Int32(ceil(Double(dropTime) * 1000.0))`, so the `Double` overload answers as C's call does.
This is the one place a body writes a conversion Raven did not write, and a Raven explicit cast inside it, `(float)pm->ps->speed`, stays as `Float(ps.speed)`.
A `float` stored into an `int` takes `Int32(...)` at the store, the mirror of the next rule, so `ps.gravity = 1.0f` reads `ps.gravity = Int32(1.0)`.
An `int` stored into a `float` with no operator between them takes `Float(...)` at the store, `ps.speed = Float(ps.basespeed)`, because Swift has no conversion on assignment and no operator reaches `=`.
The same holds for an `int` in a float table, `Float(JUMP_VELOCITY)`. The site carries no Port-note.
Raven passes an `int` to an `unsigned` parameter, and C converts the value with no cast on the page.
The callee takes a second overload with an `Int32` parameter, which converts the value once inside it, as `srand` in `Sources/JKAMP_BG/bg_lib.swift` does.
So a body writes `srand(randomSeed)` as Raven wrote it, with no cast and no Port-note.
Raven's `fabs` and `fabsf` are both `abs`, because Swift deprecates Foundation's `fabs` and `fabsf`, and `LIBC_SPELLINGS` of `rulings.py` holds this spelling.

### `#ifdef`

A `#ifdef` takes the native build's branch. The other branch is not written, and it gets no Port-note, because it is dead by the build's own choice.
A define with no body, `_JK2MP`, `MISSIONPACK`, `BOT_STRAFE_AVOIDANCE`, an include guard, is a switch of the build, fixed by the parse's defines in `tools/oracle-closure/modules/mp-game.py`, Raven's release configuration, and it is never a Swift name.
Raven's `#ifdef QAGAME` in a bg body is the one exception, and it is `if bg.consumer == .game { ... } else { ... }`, with both arms on the page.

### An assignment inside an expression

Raven's assignment inside an expression lifts to its own statement before the enclosing statement, and the expression reads the variable.
So `if ((ent = G_Spawn()) != NULL)` reads `ent = G_Spawn()` and then `if ent != nil`.
A compound store lifts the inner store first, then the outer one.
A store inside an else-if test opens the else block, because it runs only when the first test fails.
Inside a `while` test, when the stored value is optional and the test is Raven's NULL test, the loop is `while let next = <value>`, the first body line is the store, and a read where Raven dereferenced is the force unwrap:

```swift
while let next = G_Find(spot, \.classname, "info_player_deathmatch") {
    spot = next
    ...
}
```

When a statement after the loop reads the loop variable, the line `spot = nil` follows the loop with no comment, because C leaves the variable NULL when the loop ends and `while let` does not.
When nothing after the loop reads the variable, no line follows the loop.
A loop with a `break` and a later read of the loop variable takes the step at the bottom instead, because the two exits leave the variable in different states.
The search starts before the loop, the loop tests the variable itself, and the step is the last statement of the body:

```swift
spot = G_Find(nil, \.classname, "info_player_deathmatch")
while let s = spot {
    if (s.spawnflags & 1) != 0 { break }
    spot = G_Find(s, \.classname, "info_player_deathmatch")
}
```

On the `break`, the variable is the found entity, and on exhaustion it is `nil`, so no line follows the loop.

Any other `while` test with a store is `while true`, the lifted store, and the test as a break at the top, `if !(<test>) { break }`.
A store inside a `for` test or a `do`-`while` test, inside the right side of `&&` or `||`, or inside an arm of `?:` keeps its hole, because a line before the statement runs at the wrong time there.

### The `for` loop

A `for` loop is `init; while test { body; step }`.
A `continue` in the body runs the step first, on the line before it, as Raven's loop does.
A `goto` that became a labeled `continue` of an outer loop skips that loop's step, so the loop keeps a Port-note and a `portMissing` marker.

A `goto` is restructured with the smallest change that preserves Raven's control flow, per rule 10.

A `switch` with fallthrough uses Swift's `fallthrough` keyword, case for case, in Raven's order.

### The C character buffer

`Sources/JKAShared/CharBuf.swift` is a fixed-size byte buffer, `var readBuf = CharBuf(128)` for Raven's `char readBuf[128]`.
Any integer indexes it, and its subscript is generic in what it returns and stores, sign-extending a byte on the way out as C does for a signed `char` and truncating on the way in.
So `c1 = s1[i1]` reads Raven's `c1 = *s1` with `c1` declared `Int32`, and `readBuf[c] = powerBuf[i]` moves a byte.
`String(readBuf)` reads up to the first NUL, and a string literal converts to a `CharBuf` where Raven assigns one.
A `String` parameter a body walks by byte becomes a `CharBuf` at the top of the body, `let s1 = CharBuf(s1)`, and Raven's `*s1++` is the read plus `i1 += 1`.
`Int32.init(ascii: Unicode.Scalar)` in `JKAShared` spells Raven's `'a'` as `Int32(ascii: "a")`, one call for one literal, so `c1 -= ('a' - 'A')` reads `c1 -= (Int32(ascii: "a") - Int32(ascii: "A"))`.
A pointer into the buffer, Raven's `&skinName[len-3]` or the `char *slash` that `Q_strrchr` returns, is its byte offset, an `Int32`.

A truth test on a record's `char name[N]` field reads the field's `String`.
So `!saber->model` and `!saber->model[0]` both draft as `saber.model.isEmpty`.
When the two tests of one `||` or one `&&` draft as the same Swift text, the draft writes that text once, and two comment lines above the statement name Raven's two tests.
The rule also holds for two tests side by side in a longer chain, such as `saber1Active && saber1->model && saber1->model[0]`, and for any other pair that drafts the same, such as `buf[i] && buf[i] != '\0'`.

## 4. The gate

Ruling of 2026-09-09. A transcriptor never runs `swift build`, not between functions and not at the end. It ports every row and stops. It never reads a compiler message, and it never fixes a build error.

A reviewer runs `swift build` once, at the end of its own file. A body that fails to compile keeps its marker and gets a Port-note carrying the compiler's first line, never a guessed fix.

The batch gate runs after every reviewer of the batch is done, and the coordinator runs it: `swift build`, `swift build -c release`, and `swift test --no-parallel`. A golden test is written per golden once the files it needs are ported in. The gate reads errors only. A warning that maps to a line Raven wrote stands, and no body line changes only to silence it. The round's report counts the warnings without failing the gate on them.
