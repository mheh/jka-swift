# Transcription

This is the working guide for the agents that port Raven's C into the Swift stubs.
A transcriptor and a reviewer are blind transcriptors: they apply the shapes below and never design.
`docs/porting-rules.md` and its ratified rulings bind. Where this guide and a rule disagree, the rule wins.

## 1. The roles

A transcriptor takes one manifest file under `.claude/manifest/<stem>.md`.
The manifest lists each function of one oracle file, with its oracle line range, its Swift stub location, and its jka-rust line range.
The transcriptor's first edit is to delete the generated header line at the top of its Swift file, the `// Generated by tools/oracle-closure/skeleton.py ... Do not edit until adopted.` line and the blank line after it, which adopts the file so a later generator run never overwrites the port.
The transcriptor reads each function's oracle slice by that line range and ports it into the Swift stub at the listed line.
It reads the oracle only. It never reads jka-rust. The port carries Raven's behavior, not jka-rust's.

A reviewer runs after all transcriptors of a batch finish. It takes one file.
For each function it reads the oracle slice, the jka-rust slice from the manifest, and the Swift body, and confirms the three agree. The reviewer fixes what this guide settles. It notes the rest as a Port-note.

Both roles are per file and per assigned block. Neither touches another file.
A batch runs ten or more files in parallel.

### The read set

Ruling of 2026-09-09. A transcriptor reads exactly this set, and nothing else:

- the oracle slice for the row it is porting, by the manifest's line range
- its own Swift stub file
- its manifest
- the state file of its target, `Sources/JKAMP_BG/bg_local.swift` or `Sources/JKAMP_GameLogic/g_local.swift`
- the lookup tool

The lookup tool is `tools/oracle-closure/lookup.py`, the only command a transcriptor runs from the repository root.

- `python3 tools/oracle-closure/lookup.py <C type>` gives the Swift view and every field.
- `python3 tools/oracle-closure/lookup.py <C type> <field>` gives one field.
- `python3 tools/oracle-closure/lookup.py <typedef or enum>` gives a scalar or enum spelling.
- `python3 tools/oracle-closure/lookup.py fn <name>` gives a function's manifest row, with its oracle range, its Swift stub line, and its state.
- `python3 tools/oracle-closure/lookup.py sig <name>` gives the signature the table gives the function today. An adopted file keeps its old stub line, so a second pass takes the parameter list from this command and not from the file.

Unknown types become Port-notes.
A reviewer reads the same set, plus the jka-rust range from the manifest.

Neither role greps across `Sources/`.
When a needed fact sits outside the read set, the agent writes a Port-note and moves on.

### The brief

Every transcriptor, reviewer, and sweep brief carries the house-style and asd-ste100 invoke lines at the start. Every sentence the agent writes itself, a Port-note, a comment, or a doc line, follows both. Raven's own comments are copied as written and are exempt.

## 2. The Port-note

A Port-note is the one way to raise a problem.
It is a comment directly above the affected line, in this form:

```swift
// Port-note: <what is missing or uncertain>
```

Place it above the function when the whole function is in doubt.

A function the transcriptor cannot port keeps its `// TODO: Port` marker and its `portMissing` body, and gains a Port-note above them.
A function ported with a doubt gets its real body and a Port-note.

`grep -rn "Port-note:" Sources/` is the docket. The user rules on it after a batch.
No question files. No messages to the user mid-batch. No invention to close a gap.

## 3. The shapes

### The stub's signature

The signature is kept as generated. Row 6 of step 2 already applied the pure-math case in `JKAShared`.
A transcriptor does not rename a parameter, reorder one, or change a return type, even where the C source suggests a cleaner shape.

A name rule lives in `tools/oracle-closure/rulings.py`, in the tables `ROOTS`, `NEVER_NULL`, `TYPES`, `RETURNS`, and `PARAMS`.
A shape rule is code in `table.py`.
A function or parameter whose C type alone does not say its Swift shape has an entry in one of the `rulings.py` tables.

A struct a header declares that no root reaches joins `ROOTS` in `rulings.py`, so it gets a view.
A struct Raven defines inside a `.c` file has its definition copied as Raven wrote it, with a `// Source:` cite, into a hand header the target's umbrella includes.
`Sources/CJKAMP_Game/include/g_types.h` is this hand header for the game target, so a view can bind over the struct.

| Raven | Swift |
|---|---|
| a non-const `vec3_t` parameter | `inout JKAShared.vec3_t`, and a call site writes `&v`. A `const vec3_t` stays by value. A non-const `vec4_t` parameter is `inout JKAShared.vec4_t` by the same rule, and a `const vec4_t` also stays by value. |
| a `vec3_t name[3]` parameter | `inout [vec3_t]`, the type `AnglesToAxis`, `AxisClear`, and `AxisCopy` take in `q_math.swift` |
| a non-const `char *` parameter of a function that is not a trap, with or without a size parameter beside it | `inout CharBuf`, and the caller passes its own buffer with `&`. A `const char *` stays `String`. |
| a function-pointer parameter | an optional Swift closure, whose parameters go through these same rows |
| a `void *` return | `UnsafeMutableRawPointer` for `BG_Alloc`, `BG_AllocUnaligned`, and `BG_TempAlloc`, and also for `B_Alloc`, `B_TempAlloc`, and `G_Alloc`. `BG_StringAlloc` and `G_NewString` return `PooledString`. |
| a pointer parameter Raven fills as a fixed set of floats, such as `float *colors` of `BG_ValidateSkinForTeam` | `inout vec3_t` |
| a `qhandle_t *` parameter of a trap or strap function | `UnsafeMutablePointer<Int32>?` |
| a `const char *` return | `String`, or `String?` where the RETURNS kind `optional_string` marks a function that returns `NULL` on one path. |
| a `char *` return | `String`. |
| a `void **` parameter | `inout OpaquePointer?` |
| a pointer to a struct pointer, in a function that is not a trap | `inout View?`, the out-param the body sets. |
| a `const char **` parameter | `inout JKAShared.TextCursor`, or `inout String` where the PARAMS kind `out_string` marks a parameter the function sets to the token instead of walking, such as `COM_ParseString`. |
| a non-const `char *` parameter of a trap with no size parameter beside it | `String`, an input the engine reads. Raven's missing `const` is habit. |
| `qint64` | `Int64`, by the TYPES map. |
| a pointer to a const scalar, such as `const float *f` of `FloatSwap` | the scalar by value, `Float`. |
| a function-pointer return, such as `PAIN_FUNC *NPC_PainFunc` | the view's callback typealias, optional, such as `EntityPain?`. |
| a `vec3_t *` parameter of a trap with a count beside it | `[JKAShared.vec3_t]` by value. |
| a `float *` return out of a static ring of temporaries, such as `tv` | `JKAShared.vec3_t` by value, RETURNS kind `vec3`. |

Three RETURNS kinds cover the `char *` return cases beyond a plain `String`.
`in_place` marks a function that rewrites its argument and returns it, such as `Q_strlwr`, `Q_strupr`, and `Q_CleanStr`.
It returns nothing, and the skeleton writes the comment `// Raven returns the argument, which the caller already holds.` above it.
`text_offset` marks a pointer into the argument or `NULL`, such as `Q_strrchr`, and it returns `Int32?`.
`text_offset_nonnull` marks the same shape with no `NULL` case, such as `COM_SkipPath`, and it returns `Int32`.
`SkipWhitespace` takes the cursor by value and returns it advanced.
It has PARAMS kind `text_cursor` and RETURNS kind `text_cursor`.

A trap's array of struct pointers is a storage table's base, and it keeps its marker under the PARAMS kind `pointer_array`.
A trap's `char *` parameter with a size beside it is already the returned `String` the engine filled.
A buffer the engine fills with no size beside it, or rewrites in place, keeps its marker under the PARAMS kinds `fill_buffer` and `in_place`.
A raw block the engine keeps, such as `trap_SV_RegisterSharedMemory`, has a PARAMS entry `raw` and is `UnsafeMutableRawPointer`.

Raven's struct of eight bytes exists because the compilers of the time had no portable 64-bit integer.
Only the byte-swap pair touches `qint64`, and a body swaps with `byteSwapped`.
Raven takes the address of a const scalar to reinterpret the bytes, and a body reads `bitPattern`.

A pointer to one vector, such as `vec4_t *c` of `COM_ParseVec4` where Raven writes `(*c)[i]`, is `inout` too.

The returned value of a function-pointer return goes nowhere but into the view's stored function, and `ent.pain = NPC_PainFunc(ent)` reads as Raven wrote it.

A trap copies a `[JKAShared.vec3_t]` parameter into a flat `[Float]` of three per vector before the syscall, because `SIMD3<Float>` strides 16 bytes and Raven's `vec3_t` is 12.
An array the engine fills, such as `areas` and `points` of `trap_AAS_TraceAreas`, keeps its marker under the PARAMS kind `out_array`.

The body of a `float *` return out of a static ring of temporaries is `vec3_t(x, y, z)`.

A body with an `inout CharBuf` parameter writes as Raven wrote, `powerOut[i] = readBuf[0]`, and `Q_strncpyz(_ dest: inout CharBuf, _ src: String, _ destsize: Int32)` ports line for line.
`BG_ParseField` takes `UnsafeMutableRawPointer` for `byte *ent` and `Slots<BgField>` for the field table, and writes through the labeled subscript of the section on typed access at a byte offset. The caller passes the entity's handle turned raw, with a one-line comment that names rule 11.
A body with an `inout vec3_t` parameter such as `colors` drops the `&& colors` half of Raven's guard, and carries the null-guard Port-note this guide already describes.
A caller that passed `NULL` for that parameter passes a scratch local instead, `var colors = vec3_t(0, 0, 0)`, and reads nothing from it.
A caller of a trap or strap function writes `nil` where Raven wrote `NULL` for a `qhandle_t *` parameter.
The pointer stays inside generated code under rule 11, and no ported body indexes it.
An `int *` or `float *` parameter whose pointee is `qhandle_t` is not an `inout` scalar.

### Vectors and the vector macros

`vec3_t` is `SIMD3<Float>`, defined at `Sources/JKAShared/Views/Vectors.swift`.
`vec4_t` is `SIMD4<Float>`.

Raven's vector macros become operators or the ported `q_math` functions in `Sources/JKAShared/q_math.swift`:

| Raven | Swift |
|---|---|
| `VectorAdd(a, b, c)` | `c = a + b`, or `_VectorAdd(a, b, &c)` |
| `VectorSubtract(a, b, c)` | `c = a - b`, or `_VectorSubtract(a, b, &c)` |
| `VectorScale(a, s, b)` | `b = a * s`, or `_VectorScale(a, s, &b)` |
| `VectorCopy(a, b)` | `b = a` |
| `VectorMA(a, s, b, c)` | `_VectorMA(a, s, b, &c)` |
| `VectorNegate(a, b)` | `b = -a` |
| `VectorClear(a)` | `a = vec3_t(0, 0, 0)` |
| `VectorSet(a, x, y, z)` | `a = vec3_t(x, y, z)` |
| `DotProduct(a, b)` | `_DotProduct(a, b)` |

`ANGLE2SHORT` and `SHORT2ANGLE` are functions in `q_math.swift`, beside `SnapVector`.

A reduction such as `DotProduct` always uses the ported function, never a SIMD sum.
A SIMD sum may reassociate the terms, and that changes the float bit pattern the oracle produced.
`_DotProduct` at `Sources/JKAShared/q_math.swift:868` keeps Raven's scalar order for this reason:

```swift
/// A SIMD reduction may reassociate, so the sum keeps Raven's scalar order.
/// Source: oracle/codemp/game/q_math.c:1221
public func _DotProduct(_ v1: vec3_t, _ v2: vec3_t) -> vec_t {
    v1[0] * v2[0] + v1[1] * v2[1] + v1[2] * v2[2]
}
```

### Engine memory through views

Engine memory is reached through the views: `Entity`, `Client`, `Trace`, `PlayerState`, and the rest under `Generated/Views/`.
A view's fields read and write through the C struct behind it. `ent->r.absmin` becomes `ent.r.absmin`.
`Sources/JKAMP_Game/Generated/Views/Entity.swift` shows the shape: a stored pointer, and a computed property per C field.
Every generated view carries `public static let byteCount`, the size of one slot in bytes, for a module that allocates its own slot and cannot see the C type.
It also carries `public static let stride`, the distance between two slots of a C array of the type, for a `Slots` over one.

Every generated view has, beside `init(handle:)`, `public init(_ raw: UnsafeMutableRawPointer)` and `public init(_ other: some HandleView)`.
A body writes `View(x)` where and only where Raven wrote an explicit cast to that struct's pointer, from a raw pointer or from another struct's pointer, so `((gentity_t *)(ent))->s.number` reads `BgEntity(ent).s.number` in bg, and `(gentity_t *)bgEnt` is `Entity(bgEnt)` in the game.
A cast to a view the body already holds, such as a bg body that passes its `BgEntity` to a bg channel function, is dropped without a note.
The `handle:` form stays inside generated code under rule 11, and a signature keeps the plain view type Raven's parameter had, never a generic or protocol parameter that absorbs the cast.
`views.py` has a `NEVER_NULL` table beside `ROOTS`, keyed by struct and field, for a pointer field Raven's callers always set.
A field in the table is generated non-optional, and its getter traps with the field's name when the pointer is NULL, the one divergence rule 19 allows.
`pmove_t.ps`, `pmove_t.trace`, and `pmove_t.pointcontents` are in it, so a body reads `bg.pm.ps.velocity` for `pm->ps->velocity` with no bind. A field joins the table only by a ruling, never by a transcriptor's guess.
A view parameter is non-optional, so a body drops Raven's null guard on it and carries the Port-note `// Raven guards a NULL ps here. The view is non-optional, so the guard has no Swift form.`
A caller that holds an optional view unwraps it at the call site, in Raven's control shape: `guard let ... else { return }` where Raven wrote an early-out, and `if let ... { }` where Raven wrapped a block. No force unwrap appears. A guard that does other work on the NULL path keeps a Port-note.

### A scratch C struct on the stack

A scratch C struct on the stack uses a `scratch` helper on its view, for example `Trace.scratch { tr in ... }`:

```swift
let direct = Trace.scratch { tr in
    trap_Trace(tr, origin, vec3_origin, vec3_origin, dest, ENTITYNUM_NONE, MASK_SOLID)
    return tr.fraction == 1.0 || Int32(tr.entityNum) == targ.s.number
}
```

A view that has no `scratch` helper yet gets a Port-note. The transcriptor does not add the helper itself.

### A file-scope static or a static local

A Raven file-scope static, or a static local, becomes a stored property on `GameWorld` in `g_local.swift`, under rule 3.
Ported bodies reach it through the `world` global. The transcriptor adds the property with Raven's name and a `/// Source:` line, for example:

```swift
/// Raven's `static unsigned long holdrand` of `q_math.c`, which the game module owns one copy of.
/// Source: oracle/codemp/game/q_math.c:1432
var rng = Rng()
```

`bg_itemlist`, `weaponData`, and `ammoData` are C storage in `Sources/CJKAMP/bg_tables.c`, with Raven's initializers as written, and `Sources/JKAMP/BgTables.swift` reaches each one as a `Slots` over the C array, with the view's `stride`, because the view target is the one Swift module that imports the C target and can take the address of the C array, and `bg_numItems` reads the C global, so a body reads `bg_itemlist[i].giTag`.
The header `Sources/CJKAMP/include/bg_tables.h` declares each array with a written bound, because the Swift importer drops an array of unknown bound, and clang checks the bound against the initializer.
Every other struct-typed table Raven declares at file scope, such as `fields[]` of `g_spawn.c`, is C storage the same way. The stub of a `.c` file carries one entry per file-scope variable, above its first function.
A variable the module never assigns is a typed `let` with a `portMissing` initializer and a `// Raven wrote:` line, and the transcriptor replaces the initializer with Raven's data.
A variable the module assigns is a stored property of the state object, `BgState` or `GameWorld`, with Raven's initializer, spelled `bg.name` or `world.name` in a body, and its stub entry carries `// TODO: Port global name` and `// Raven wrote:`.
A variable Raven declares with no initializer is his all the same, zeroed by the loader, and its entry says C's zero where the initializer would be.
A file-scope array of struct pointers, such as `gWPArray`, is C storage the generator writes, one `Sources/CJKAMP_Game/Generated/<stem>.c` per Raven file, declared for the umbrella in `include/g_storage.h`.
The view target holds a `Slots` of optional views over it in `Sources/JKAMP_Game/Generated/Storage/<stem>.swift`, and the stub carries the name at Raven's line, `var gWPArray: Slots<JKAMP.Wpobject?> { JKAMP_Game.gWPArray }`.
A body reads `gWPArray[i]?.inuse` and writes `gWPArray[i] = Wpobject(B_Alloc(...))`, and a trap that takes the table, `trap_Bot_UpdateWaypoints`, takes the `Slots` and hands the engine its base.
A body macro that names a local, such as `SLOPERECALCVAR`, is spelled as its expansion at the site, `pm.ps.slopeRecalcTime`, with Raven's macro name in a one-line comment at the first use.

### A static in a bg file

Ruling of 2026-09-09. `JKAMP_BG` cannot see `GameWorld`, and cgame links the same bg code with its own instance.
A Raven static in a `bg_*.c` file lives on `final class BgState`, in the hand file `Sources/JKAMP_BG/bg_local.swift`, behind `nonisolated(unsafe) var bg = BgState()`, the same shape as `world`.
The transcriptor adds the property with Raven's name and a `/// Source:` line, and writes `bg.name`.

A scalar static is a Swift stored property. A struct static such as `pml`, which Raven's bodies read through a view, gets C storage owned by `BgState`, with the view over it, the pattern `GameMemory` uses at `Sources/JKAMP_Game/GameMemory.swift`.
A pointer static such as `pm` is the view of the caller's memory, set per call. A test resets state with `bg = BgState()`.
A static local that every path of the body writes before it reads is scratch, Raven's habit of keeping vectors off the stack, and it is a local of the body, declared where Raven declared it with his initializer.
The 23 statics of `BG_UpdateLookAngles` and `BG_G2PlayerAngles` are this shape, and none of them sits on `BgState`.

A transcriptor adds a property to `bg_local.swift` with Raven's name and a `/// Source:` line.

`bg_pool` is one raw allocation of `MAX_POOL_SIZE` bytes, `bg.pool`, made at the consumer's install and never freed. `poolSize` and `poolTail` sit on `BgState`.
`MAX_POOL_SIZE` is `var MAX_POOL_SIZE: Int32 { bg.maxPoolSize }` in `bg_local.swift`, so a body reads Raven's name.

### The bg channel

`tools/oracle-closure/channel.py` generates `Sources/JKAMP_BG/Generated/bg_strap.swift` from `bg_strap.h`: one bare `strap_` function per declaration, each forwarding to a closure on `bg.straps`, the `BgStraps` struct. A declaration the table cannot map gets a `TODO: Port signature` marker instead of a closure.
Every `trap_` a bg body calls joins `bg_strap.swift` beside the header's declarations, with the shape of the game's `g_syscalls.c` definition, so a body reads `trap_FS_FOpenFile(fileName, &fh, FS_READ)` as Raven wrote it.
A trap only the cgame module defines is out of the game's parse, so a cgame arm that calls one carries a Port-note that names it.
The same generator writes `Sources/JKAMP_BG/Generated/bg_callbacks.swift`, which holds one bare function per game function a bg body calls by name, each forwarding to a closure on `bg.callbacks`, the `BgCallbacks` struct, in the same shape.
It also writes `Sources/JKAMP_GameLogic/Generated/BgChannel.swift`, whose `installBgChannel()` points every closure at the game function of the same name. A bg body spells `strap_G2API_SetBoneAngles(...)` and `G_NewString(...)` as Raven wrote them.
The bg side of the channel names `JKAMP.BgEntity` where the game function takes an `Entity`, because the `Entity` view lives in the game target that bg cannot import. `installBgChannel()` turns the one into the other by its handle under rule 11.
`vmCvar_t` has the view `VmCvar`, and `bg_fighterAltControl` is `var bg_fighterAltControl: VmCvar { bg.fighterAltControl }` in `bg_local.swift`, a view over the game's cvar memory, so a body reads `bg_fighterAltControl.integer`. Until the game's cvar storage exists, the default is a view over one zeroed `vmCvar_t` the state allocates, so `.integer` reads 0, Raven's default.

### A `char *` at runtime

A `char *` at runtime comes from the world's string pool of rule 9, `Sources/JKAShared/Views/StringPool.swift`.
`world.strings.intern("text")` returns a `PooledString`, the pointer type a `char *` field takes.
A `PooledString` compares by pointer, as Raven's `char *` compare did, so `ent.classname == "noclass"` reads as Raven's `strcmp` did.

A Raven store such as `ent->think = Name` uses the generated thunk in `Callbacks.swift`, for example `ent.think = Think.G_FreeEntity`.

### The five `holdrand` draws

The five `holdrand` draws are the bare forwarders in `g_local.swift`: `flrand`, `irand`, `Q_flrand`, `Q_irand`, `Rand_Init`.

### A call to a not yet ported function

A call to a function not yet ported stays a call to its stub.
The stub compiles and traps at runtime with `portMissing`. The transcriptor does not port the callee to unblock the caller.

### Primitive types

`qboolean` is `Bool`. `int` is `Int32`. `float` is `Float`.
An array index is the C constant or variable Raven wrote, for example `vec[YAW]` and `ps.stats[STAT_HEALTH]`, never `Int(...)`. Every array in the port takes any C integer index.
A C enum is an `Int32` typealias, and each case is a bare `Int32` constant with Raven's name.
A body compares, stores, switches, and shifts it exactly as Raven wrote it. `.rawValue` and `EnumName(rawValue:)` never appear.
An unsigned hex mask Raven applies to an `int`, such as `0xfffffffc`, is spelled as the complement of the low bits, `~0x0000_0003`, the same bit pattern with no cast, and one comment line at the site says what Raven wrote.

A cast Raven wrote explicitly stays on the page, so `(int)v[0]` is `Int32(v[0])` and `(float)x` is `Float(x)`. A body never adds a cast Raven did not write.
`Sources/JKAShared/Promotion.swift` defines the arithmetic and comparison operators between `Int32` and `Float`, both orders, and the compound assignments, and each one promotes the integer as C does.
So `ps.velocity[2] -= ps.gravity * bg.pml.frametime` and `ps.origin[2] + MINS_Z + 1` are Raven's lines.
Swift reads `0.1` beside a `Float` as a `Float`, which changes the bits Raven's double math sets.
So a body writes `Double(x)` on each float operand of an expression that holds a double literal, and `Float(...)` once at the store, `drop += Float(Double(speed) * 0.1 * Double(bg.pml.frametime))`.
This is the one place a body writes a conversion Raven did not write, and a Raven explicit cast inside it, `(float)pm->ps->speed`, stays as `Float(ps.speed)`.
An `int` stored into a `float` with no operator between them takes `Float(...)` at the store, `ps.speed = Float(ps.basespeed)`, because Swift has no conversion on assignment and no operator reaches `=`.
The same holds for an `int` in a float table, `Float(JUMP_VELOCITY)`. The site carries no Port-note.

### `#ifdef`

A `#ifdef` takes the native build's branch. The other branch is not written, and it gets no Port-note, because it is dead by the build's own choice.
Raven's `#ifdef QAGAME` in a bg body is the one exception, and it is `if bg.consumer == .game { ... } else { ... }`, with both arms on the page.

### `goto`

A `goto` is restructured with the smallest change that preserves Raven's control flow, per rule 10.
It gets a Port-note naming the label, so the reviewer and the user can check the restructuring against Raven's intent.

### `switch` with fallthrough

A `switch` with fallthrough uses Swift's `fallthrough` keyword, case for case, in Raven's order.

### The C character buffer

`Sources/JKAShared/CharBuf.swift` is a fixed-size byte buffer, `var readBuf = CharBuf(128)` for Raven's `char readBuf[128]`.
Any integer indexes it, and its subscript is generic in what it returns and stores, sign-extending a byte on the way out as C does for a signed `char` and truncating on the way in.
So `c1 = s1[i1]` reads Raven's `c1 = *s1` with `c1` declared `Int32`, and `readBuf[c] = powerBuf[i]` moves a byte.
`String(readBuf)` reads up to the first NUL, and a string literal converts to a `CharBuf` where Raven assigns one.
A `String` parameter a body walks by byte becomes a `CharBuf` at the top of the body, `let s1 = CharBuf(s1)`, and Raven's `*s1++` is the read plus `i1 += 1`.
`Int32.init(ascii: Unicode.Scalar)` in `JKAShared` spells Raven's `'a'` as `Int32(ascii: "a")`, one call for one literal, so `c1 -= ('a' - 'A')` reads `c1 -= (Int32(ascii: "a") - Int32(ascii: "A"))`.
A pointer into the buffer, Raven's `&skinName[len-3]` or the `char *slash` that `Q_strrchr` returns, is its byte offset, an `Int32`.
A read through it is the suffix subscript, `Q_strncmp("red", skinName[start...], 3)`, and a write through it is `strcpy(&GLAName, "/animation.cfg", at: slash)`.
`strchr`, `strstr`, and `Q_strrchr` return that offset as `Int32?`, so `if let slash` is Raven's `if (slash)`.

### The text cursor

`Sources/JKAShared/TextCursor.swift` is Raven's `const char *p` into a text buffer, a `CharBuf` and a byte offset `Int32?`, where `nil` is his `NULL`.
`isNull`, `byte`, and `advance()` are the reads and the step.
`token = COM_ParseExt(&p, true)` reads as Raven wrote it.

### C string functions

`Q_stricmp`, `Com_sprintf`, `strcpy`, and the rest call the ported `q_shared` functions where a port exists.
Where no port exists, the transcriptor adds a Port-note, because the exact C semantics are not proven.
`q_shared.c` is compiled into every module the same as `q_math.c`, so its port is `Sources/JKAShared/q_shared.c.swift`, named with the `.c` because the re-export of `q_shared.h` already holds the stem in that module. A body reaches `Q_stricmp`, `Q_stricmpn`, and `Q_strncmp` there, and each of the three has a `CharBuf` overload.
`Sources/JKAShared/CString.swift` holds the libc names Raven calls, `atoi`, `atof`, `strcpy`, `strncpy`, `strlen`, `strcmp`, `strchr`, and `strstr`, with C semantics.
Each one works over `CharBuf` and `String`, `strcpy` also takes a raw destination, and `strlen` returns `Int32`, narrowed once inside it.
`PooledString` has `init(_ raw: UnsafeMutableRawPointer)`, so `BG_StringAlloc` reads `strcpy(dest, source)` then `return PooledString(dest)`.
Raven's `...` is `_ args: any JKAShared.FormatArg...`, and `Sources/JKAShared/Format.swift` formats it with the `printf` subset the game uses, `%i`, `%d`, `%s`, and `%f` with a width, a precision, and the left-align flag.
`va` returns that text, so `strcpy(&powerOut, va("%i-", maxRank))` is Raven's line, and `Com_Printf`, `G_Printf`, and `Com_Error` format the same way.
A specifier outside the subset is a precondition failure, so a new shape surfaces at once.
`sscanf` lives in `Sources/JKAShared/Scan.swift`, one overload per target shape in use, `inout vec3_t` for `"%f %f %f"`, `inout Float` for `"%f"`, and `inout Int32` for `"%d"`, each returning the count read as C does.
Swift has no `inout` variadic, so `sscanf(value, "%f %f %f", &vec)` is Raven's call with the three addresses as the one vector, and each overload checks its format.
`Q_strlwr`, `Q_strupr`, and `Q_CleanStr` rewrite a local buffer in place, `Q_CleanStr(&netname)`, and each has a value form, `String` to `String`, for the two shapes with no `CharBuf` behind them.
A view's `char` array writes back through its setter, `tagOwner.name = Q_strlwr(tagOwner.name)`, into the same bytes.
A pooled string takes the value form before the pool, `ent.NPC_type = G_NewString(Q_strlwr(ent.NPC_type.string))`, because the pool holds one copy per text and a rewrite in place would change every holder. Raven lowercased after his copy, and the result is the same string.
`Parse1DMatrix`, `Parse2DMatrix`, and `Parse3DMatrix` take their matrix as `inout [Float]`, and the 2D and 3D bodies fill a row-sized local through the 1D function and copy it into place, `m[i * x ..< i * x + x]`, where Raven walked the pointer with `m + i * x`.

### Engine and print calls

`Com_Printf`, `G_Printf`, and every `trap_*` call are calls to the existing functions. The transcriptor does not stub these.
A trap's return is `@discardableResult`, and so is a strap's or a callback's, because Raven drops it at most sites and C never warned, so a body writes his line with no `_ =`.

### Comments

Raven's comment block above a function stays as the `/** */` the stub already carries.
Raven's inline comments stay in place, verbatim, inside the ported body.
A new comment the transcriptor writes follows the house style: STE prose, one sentence per line, no em dashes.

### Typed access at a byte offset

`Sources/JKAShared/Views/RawField.swift` extends `UnsafeMutableRawPointer` with one labeled subscript per C type Raven casts to at an offset, each taking any integer offset.
`b[int: f.ofs]` stores an `Int32`, `b[float: f.ofs]` a `Float`, `b[float: f.ofs, 1]` the second float after the offset, and `b[string: f.ofs]` the raw pointer of a `PooledString`.
`BG_ParseField` reads `b[int: f.ofs] = atoi(value)` for Raven's `*(int *)(b+f->ofs) = atoi(value)`, and a body never writes `storeBytes` or `MemoryLayout`.
The same file defines `+` and `-` between a raw pointer and any integer, so `BG_Alloc` reads `return bg.pool + (bg.poolSize - size)` for Raven's `&bg_pool[bg_poolSize-size]`.

### No `Unsafe` type

No `Unsafe` type appears in a logic target, under rule 11. A pointer stays inside the view target.
A transcriptor that finds it needs one stops and writes a Port-note instead.

## 4. The gate

Ruling of 2026-09-09. A transcriptor never runs `swift build`, not between functions and not at the end. It ports every row and stops. It never reads a compiler message, and it never fixes a build error.

A reviewer runs `swift build` once, at the end of its own file. A body that fails to compile keeps its marker and gets a Port-note carrying the compiler's first line, never a guessed fix.

The batch gate runs after every reviewer of the batch is done, and the coordinator runs it: `swift build`, `swift build -c release`, and `swift test`. A golden test is written per golden once the files it needs are ported in.

## 5. The finished report

Each agent reports back in under 20 lines:

- the functions it ported
- the functions it left with a marker, and the Port-note above each one
- any Port-note left in a ported body
